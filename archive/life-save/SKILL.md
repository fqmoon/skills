# Life Save

把本次会话中值得长期留下的结论，写进 life（一生项目）。

**它不是「存一下」。** 完整动作是五步：

```text
提炼 → 查现状（调 life-load）→ 归类 → 并进子文档 → 同步入口
```

**第二步不能省，也不能靠记忆。** 写之前必须先看树里现在是什么状态：目标文件里已经有什么、该并入哪一节、有没有要改写的旧结论、有没有要顺手修的错误。

缺任何一步，资料树都会退化：不查现状就写，会写出重复条目和漂移的入口；只提炼不归类，文件会越开越多；只并进不同步入口，索引会漂移。

**它是这棵树唯一的写者** —— 写入和维护都归它。写者同时是维护者，因为维护就是一次「看到现状 → 改」。

# 它是交互 skill

**新增不问；改和删要先问；结束一定汇报。**

| 动作 | 问不问 | 为什么 |
|---|---|---|
| **新增** | 不问 | 非破坏性 —— 只是多一条 |
| **改**（改写被推翻的结论） | **先问** | 破坏性 —— 旧的那句会消失 |
| **删** | **先问** | 破坏性 —— 同上 |

**一次列清单，一次问。** 一次收尾有多处待改 / 待删时，合并成一份清单问一次，不要一条一问。

**结束必须汇报变化了哪些** —— 无论有没有改删。这是你唯一能看到这次写了什么的地方（写进盘里的东西你不会主动去看）。

| 这次干了什么 | 汇报什么 |
|---|---|
| 只新增 | 新增了哪几条 → 落到哪个文件 |
| 有改 / 有删 | 先问（清单）→ 做完 → 汇报最终变化 |
| 什么都没写 | 直说「这次没有值得留下的」 |

# 建树

不在这里做。树不存在时（根目录或 `README.md` 缺失）**停下报告**，请用户跑 `life-init` —— 它负责目录、入口、git、远端与定时推送，且禁止模型自行触发。

不要退化成写散文件（`~/life-notes.md` 之类），也不要临时建一个没有 git、没有入口的目录 —— 那会造出第二份真相。

# 提炼出什么

**不是筛选，是蒸馏。** 整场会话是原料，产物只有三类：

| 产物 | 问自己 | 落到哪 |
|---|---|---|
| **方向**（intent） | 这次之后，我要的东西变了吗？ | 方向那一页，覆盖旧的 |
| **决定**（ADR） | 有没有做一个关掉一批选项的决定？ | 主题文件，追加，永不合并 |
| **判据** | 有没有一条下次能省一次犹豫的规则？ | 主题文件，连来由一起 |

三种产物都要求**主语是「我」**。主语是项目 / 模块 / 系统 → 那是项目文档里的东西（`intent` / `ADR` / `progress` / `debt`），不进这里。

**决定必须写被否决的选项** —— 只写「我选了 X」等于没记，下次会把否决项重新认真考虑一遍。被推翻的决定不删，标「已推翻」。

**判据必须带来由** —— 留到「下次能判断这算不算同一类」为止；只有结论没有来由的是教条。

两种提炼失败，方向相反：只留记录没有产物（树变流水账）；只留产物没有来由（情况变一点就套不上）。

明确不留下：本次做了什么、调试过程、已完成事项、只对本次任务有意义的状态。

判据的形态、与项目文档 / 笔记的边界，见 `life` Skill；拿不准该提炼成哪一类时用它，不要凭记忆判断。

**遇到模糊或冲突，不丢，也不并成一条假的确定：** 模糊的标成不确定；两难的分情形写清各自条件（收在同一条里）；同一情形两个相反说法才是漂移，必须合并。判据能被人照着用才算判据 —— 拿着它做不出和你一样的选择，那还是记录。

**绝不能留下**：凭据与密钥、别人的私事 —— 任何「删掉会比留着便宜」的东西。

这一条比上面两条更硬。上面判断错了只是噪音，这里判断错了是**留在盘上的债** —— 而且事后删也要先问，补救不及时。

# 归类

**先找已有的子文档** —— 这一步由 `life-load` 给出，不要靠自己回忆。**不要急着新建**，按主题匹配，不按本次任务匹配。

新建子文档的门槛只有一条：

> **它会被独立检索** —— 有人可能只想找这一件事。

不满足就并进最接近的已有文件。

新增时的命名：

- **不带日期** —— 子文档是活文档，会被改写；
- 用**一年后还在的词**，不用当前这件事的词；
- 名词短语，用你会说出口的词。

# 写成什么样

条目 = **一句结论 + 日期**。

```markdown
## <子主题>

- 结论内容。 (2026-11-05)
- 结论内容。 (2026-11-05)
  - 只在下次会用到时，才补最多两三条细节。
```

- 二级标题就是子主题，也是检索单位 —— 标题要能被目标对上；
- **日期必留** —— 它是判断新鲜度的**唯一**依据。**所有条目一视同仁**：不区分内容类型、不预判谁会过期，新鲜度只看这一个数；
- 不写叙述，不写「本次讨论了」。

# 原始材料放 refer/

默认**只放链接**，不复制内容：

```markdown
- 结论内容。 (2026-11-05)
  - 来源：<绝对路径 或 URL>（取自 2026-11-05）
```

只有**用户明确指定要存**时，才把材料复制进 `refer/`：

- **带日期**命名 —— 与子文档相反，因为它是快照、不改写；
- 文件开头自带来源信息：从哪来、什么时候取的；
- 子文档里指向它，而不是把内容摊进子文档。

判据与 `myenv` 一致：**Skill 自己判断不构成复制授权。**

# 只留当前有效结论

被推翻的结论**直接改写成新的**，不留墓碑：

```text
不要：曾经认为 X，后来改为 Y。
要：  Y。
```

保留日期即可，不需要保留 X。

# 删除与归档

对一条要动的内容，三条路：

| 情形 | 默认建议 | 为什么 |
|---|---|---|
| **不该存在**（凭据、私事、错贴、噪音） | **直接删** | 它是**事实** —— 删掉比留着便宜 |
| **没用了**（判断：这条大概不会再被需要） | **归档** | 它是**判断** —— 判断不该有删除权，软删就够 |
| 被推翻，但有替代结论 | **改写** | 内容还有效，只是换了形态 |

**三条路都要先问。** 我把待动的列成清单、**每条带一个建议**，你逐条确认或者改成别的。

**归档是什么**：把内容**移出检索范围但保留** —— 装进 `archive/`，入口那行删掉。它从装载里消失，但还在盘上。

**所以「没用了」不再等于「删掉」** —— 那是判断，判断只能软删。只有事实（不该存在）才真删。

## 谁能删 / 谁能归档

**在场就能，且都要先问。** 判据不是在哪个 Skill，是**能不能立刻问一句并拿到回答**。

- `life-load` —— **不解锁**。它在装载路径上（每次装载都跑），必须便宜、无副作用；删除和归档都是要问、要多步清理的重动作，不该挂在热路径上。撞到不该存在的内容，只有**报告权**；
- `life-save` —— 收尾时你天然在场 → 能问 → 能做。

**所以敏感内容也是「发现 → 报告 → 你确认 → 才删」**，没有「自己删了再说」这一路。

## 动干净清单

**先分清动的是哪一层** —— 层级错了会动到不该动的：

| 动什么 | 删 | 归档 |
|---|---|---|
| **条目**（一个 H2 / 一条） | 删条目；若它代表那个文件的主要内容，改入口摘要 | 把那一条**连同日期**追加到 `archive/<原文件名>`，正文里删掉 —— 文件还在，所以入口行和 `hits.md` 都不动 |
| **文件**（最后一个条目处理完后） | 删文件 + 入口行 + `hits.md` 行 + 「最近变化」那行 + 只删**没有被引用的** refer 快照 | 移入 `archive/` + 删入口行 + 删 `hits.md` 行 + 「最近变化」照写 |
| **refer 快照** | 只在确认没有子文档引用时才删（一份可能被多条引用） | —— |

**`archive/` 里的内容不参与检索** —— 装载不读它，入口不列它。它是「我不删，但我不再指望它」。

**「最近变化」照写** —— 它只记文件名 + 日期、不记内容，所以不泄露任何东西；不写反而让那个表失真。

# 同步入口

**改动任何子文档后，必须同步入口 README 里对应那一行，并更新「最近变化」（保留最近 5 条）。**

「最近变化」的行只写**文件名 + 日期**（如 `agent-tooling.md  2026-11-05`），**不写内容** —— 它只回答「哪几个文件最近动过」，装载时优先看这几个。因为不记内容，删除时也照写。

入口那一行同时承担索引与别名（「也叫……」）—— 这是唯一的同步点，不要在每个文件里再放一份关键词。

# 什么时候写

- 任务完成、阶段交付时；
- 用户明确表示告一段落时；
- 过程中遇到值得单独记下的坑时（允许只写一行 —— 那类信息当时最鲜活）。

# 提交（不推送）

收尾时就在本地提交 —— 明天的机器只看得到 diff，写不出 why。

```bash
git -C "$ROOT" add -A
git -C "$ROOT" -c user.name=life -c user.email=life@localhost -c core.quotepath=false \
  commit -m "<第一行：一句话>" -m "<其后：分条>"
```

**推送不在这里做**：定时任务只负责把已提交的东西推上去（见 `life-init`）。

**消息格式**：第一行一句话说清这一批改了什么（**不加前缀、不写日期**），其后分条、每条一件事、以动词开头。含糊等于没写 —— 它整条就是 `git log --oneline` 的内容。

# 维护（顺手做的结构调整）

**维护归本 Skill** —— 没有单独的维护 skill。这几件事**看到就做**，不攒着：

| 看到什么 | 做什么 |
|---|---|
| 某个二级标题下超过约 10 条 | **拆成独立子文档** —— 入口加行，**旧标题作为别名留在入口** |
| 两个子文档其实讲同一件事 | **并为一个** —— 被并掉的名字作为别名留在入口 |
| `refer/` 里有没被任何条目引用的文件 | **报告，不删**（可能是你手动放的） |
| `hits.md` 里有指向已删文件的行 | 直接删掉那一行 |
| `hits.md` 显示某文件从没被读过 / 反复被读 | **改入口那一行的描述** —— 那是入口的问题，不是内容的问题 |

它们是**改结构**，不是改结论 —— 但一样要**先问**（都不可逆）。

**归档不在这里** —— 它是「删除与归档」那节里的一个选择，由你当场定，不是巡检时按判据算出来的。

# 不负责

- **不做「定期通读整棵树」的巡检** —— 没有单独的维护 skill。树的健康靠两件事维持：每次收尾做对（上面那四步），以及**结束时的汇报**（你能看到这次动了哪些文件）。代价是**漂移没有兜底** —— 哪次忘了同步入口，就要等下次有人碰那个文件才发现；
- 不维护条目之间的链接、标签或双链 —— 条目就用普通语言写，读的时候不需要跳转；
- 不记录任务进度。判据是：**下次做同类事会用到 → 这里；下次接着做这件事 → `progress` / 项目的 Execution Plan**；
- 不写入当前有效结论之外的历史。

# 核心原则

> **提炼出结论、并进对的文件、同步入口那一行；只留当前有效版本。**
