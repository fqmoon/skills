用途
- 在当前会话结束前生成或更新交接文档。
- 让新会话能够直接续接尚未完成的工作。
- 只保留继续工作真正需要的信息。
- 删除已经完成、失效或与后续工作无关的信息。
- 让未进入交接文档的信息随旧会话一起被遗忘。

输入
- 当前会话的完整历史记录。
- 当前项目的代码和文档状态。
- 现有的 FORGET.md，如果存在。
- 调用 Skill 时可以同时提供下一步工作内容。
  - 如果用户明确提供，则以用户提供的内容作为 Next Actions 的主要范围。
  - 如果用户未提供，则根据当前会话、项目状态和未完成工作，自动推导最可能的 Next Actions。
- Open Issues 不要求用户提供，由 Skill 根据当前会话、项目状态和现有 FORGET.md 自动总结。

输出
- 一个简短、可独立理解、可手工编辑的 FORGET.md。
- 文档只描述当前仍需继续处理的工作。
- 文档可以自动新增、修改、合并、移动和删除内容。

核心原则
- FORGET.md 是当前状态，不是历史记录。
- FORGET.md 是普通 Markdown 大纲，不是机器数据库。
- 用户可以随时手工编辑 FORGET.md。
- Agent 运行本 Skill 时可以自动新增、修改、合并、移动和删除内容。
- Next Actions 优先由用户意图决定。
- Open Issues 由 Skill 自动识别和维护。
- 只保留下一会话继续工作所需的信息。
- 不总结完整会话历史。
- 不保存已经完成的工作。
- 不保存仅用于解释历史过程的信息。
- 不通过否定、废弃说明、完成记录或历史回顾重新引入应该遗忘的对象。
- 文档应尽可能短，但不得遗漏继续工作所必需的信息。

交接范围
FORGET.md 只围绕两类未完成事项组织：

- Next Actions
  - 下一会话准备继续执行的工作。
  - 用户明确指定时，以用户指定的工作范围为准。
  - 用户未指定时，自动推导最可能继续的工作。

- Open Issues
  - 当前仍未解决、未确定、待验证或会影响后续工作的事项。
  - 由 Skill 自动识别，不要求用户显式提供。

其他信息没有独立存在资格。

决策、约束、事实、当前状态、路径、参数、错误信息等内容，只有在继续某个 Next Action 或理解某个 Open Issue 时确实需要，才作为补充信息保留。

如果一条信息不能支持任何仍然存在的 Next Action 或 Open Issue，则不应保留。

Next Actions
- 用户在调用 Skill 时明确提供的下一步工作，优先级最高。
- 用户明确提供工作范围时，不得用自动推导结果覆盖或无故扩大该范围。
- 用户只指定某一部分工作时，默认围绕该部分生成 Next Actions。
- 不因为会话中还存在其他讨论内容，就自动将其加入 Next Actions。
- 用户未提供下一步工作时，才自动推导最可能继续的工作。
- 自动推导时优先考虑：
  - 当前正在进行但尚未完成的工作。
  - 会话末尾明确提出但尚未执行的动作。
  - 已形成明确方案且下一步实施路径清楚的事项。
  - 当前项目状态明显指向的直接后续工作。
- 以下内容默认不自动视为 Next Action：
  - 仅讨论过的可能方案。
  - 已否定方案。
  - 模糊的未来想法。
  - 没有明确执行意图的建议。
  - 明确表示暂时不准备继续的事项。

Open Issues
- Open Issues 由 Skill 自动识别和维护。
- 包括：
  - 已发现但仍未解决的问题。
  - 尚未确定的设计或方案。
  - 仍需验证的假设。
  - 尚未回答且可能影响后续工作的关键问题。
  - 当前存在但尚未决定如何处理的异常行为。
  - 暂缓处理但仍需在未来解决的事项。
- 优先保留：
  - 与当前 Next Actions 直接相关的问题。
  - 如果遗忘，会导致下一会话重复调查、误操作或丢失重要未决状态的问题。
- 不因为问题存在就必须保留。
- 如果问题已经完整记录在正式 Issue、文档或其他持久化来源中，且无需额外交接信息，可以只保留必要引用，或不重复记录。

核心流程，如果任意一步无法安全完成，则中止运行
1. 查找 FORGET.md，检查数量 <= 1；否则中止运行。
2. 读取当前 FORGET.md，如果存在。
3. 遍历当前会话完整历史，而不是只查看最近几轮消息。
4. 必要时检查当前项目代码和正式文档，以确认事项的当前状态。
5. 确定 Next Actions：
   - 如果调用 Skill 时用户提供了下一步工作内容，以其作为主要工作范围。
   - 如果用户未提供，则根据当前会话、项目状态和未完成工作自动推导最可能的下一步工作。
6. 自动识别当前 Open Issues。
7. 找出继续 Next Actions 和理解 Open Issues 所必需、且不应依赖旧会话才能恢复的信息。
8. 将识别出的当前状态与现有 FORGET.md 对齐：
   - 新事项：添加。
   - 已有事项状态变化：直接修改。
   - 表述重复或高度重叠：合并。
   - 事项范围发生变化：重写为当前准确状态。
   - 已完成事项：删除。
   - 已取消事项：删除。
   - 已失效事项：删除。
   - 已被其他事项完全取代的事项：删除。
   - 不再被任何事项需要的附属信息：删除。
9. 整理成简短的大纲式 FORGET.md。
10. 如果不存在任何需要跨会话继续的事项，则删除 FORGET.md。
11. 不自动结束当前会话，不自动创建新会话，不自动执行 Git 操作。

完成项处理
- 已完成事项直接从 FORGET.md 删除。
- 不保留完成标记。
- 不保留完成说明。
- 不保留完成时间。
- 不保留“之前需要做”的历史。
- 删除事项时，同时删除只为该事项服务的相关信息。

例如：

删除前：

```markdown
- [NEXT] 将 WASM URL 改为由上层显式传入。
  - SDK 当前仍存在默认 WASM 路径。
  - DEMO 需要同步修改加载方式。
```

如果该工作已经完成，则整个条目直接删除。

不要改写成：

```markdown
- [DONE] WASM URL 已改为由上层显式传入。
```

也不要保留：

```markdown
- WASM URL 之前由 SDK 使用默认路径，现在已经修改完成。
```

完成意味着该信息不再需要跨会话传递。

取消和失效
以下状态通常意味着事项应删除：
- 已完成。
- 明确取消。
- 明确不再处理。
- 已被其他方案取代。
- 当前项目状态表明该事项已经不存在。
- 用户明确指出该事项不需要继续保留。

以下状态不等于完成：
- 暂缓。
- 后面再做。
- 等待确认。
- 等待产品决定。
- 待验证。
- 当前不处理但未来仍需处理。

这些情况仍属于 Open Issue 或 Next Action，应继续保留。

用户明确状态优先
- 用户明确说明某事项已完成、取消、失效或不再处理时，优先按照该状态处理。
- 用户明确指定下一步工作范围时，优先按照该范围生成 Next Actions。
- 不要因为旧会话内容、旧 FORGET 条目或历史代码状态而恢复已经被用户明确关闭的事项。
- 如果当前代码状态与用户明确陈述存在明显冲突，可以将冲突本身视为新的 Open Issue，但不得偷偷恢复已经关闭的旧事项。

必要上下文
- Next Action 或 Open Issue 可以包含少量子条目。
- 子条目只用于记录继续该事项真正需要的信息。
- 不要求使用固定的 Context、Decision、Constraint、Fact 等标签。
- 优先采用自然的大纲式表达。
- 没有必要上下文时，不添加子条目。

例如：

```markdown
- [NEXT] 调整 WASM 加载接口，由上层显式传入 URL。
  - DEMO 也需要同步修改加载方式。
  - 当前公开接口尚未确定参数名称。
```

而不是：

```markdown
- [NEXT] 调整 WASM 加载接口。
  - Context: ...
  - Decision: ...
  - Constraint: ...
  - Fact: ...
```

避免为了分类而增加结构。

信息依赖
- 每条补充信息必须至少服务于一个仍然存在的 Next Action 或 Open Issue。
- 某事项删除后，检查其补充信息是否仍被其他事项需要。
- 如果仍被其他事项需要，则保留。
- 如果不再被任何事项需要，则一并删除。
- 不保留孤立背景信息。

正式信息来源
以下信息如果可以方便、可靠地从正式项目状态中获得，通常不需要复制进 FORGET.md：
- 代码中已经明确存在的实现细节。
- 正式文档中的设计说明。
- ADR 中已经记录的长期决策。
- AGENTS.md 或类似文件中的长期工作规则。
- 正式 Issue 中已经完整记录的问题。
- Git 历史中无需特殊解释即可恢复的信息。

必要时可以保留简短引用，例如：

```markdown
- [NEXT] 按 `docs/wasm-loading.md` 中的方案完成 DEMO 接入。
```

不要复制整段正式文档内容。

例外：
- 如果不知道某个信息会导致下一会话立即误操作、重复犯错或无法继续工作，可以保留必要的最小信息。
- 即使信息存在于其他位置，如果定位成本明显高于简单保留一条短句，也可以保留。

禁止重新引入
最终 FORGET.md 不写：
- “不要使用 X”。
- “X 已废弃”。
- “之前使用 X”。
- “从 X 改成 Y”。
- “过去考虑过 X”。
- “这个问题已经解决”。
- “这个任务已经完成”。

如果 X 不再需要，只删除 X。

如果当前有效状态是 Y，只描述 Y，而且只有 Y 对尚未完成工作仍然必要时才保留。

例如：

错误：

```markdown
- [NEXT] 不要再使用默认 WASM 路径，之前方案已经废弃。
```

正确：

```markdown
- [NEXT] WASM URL 由上层应用显式传入。
```

如果连这条工作也已经完成，则两者都不保留。

手工编辑兼容
- FORGET.md 必须保持普通 Markdown，可由用户直接编辑。
- 不依赖隐藏 ID、机器生成字段、JSON、YAML 数据结构或特殊注释。
- 不要求严格固定格式。
- 用户已有的大纲结构只要清晰可理解，应尽量沿用。
- 用户手工修改后的内容视为当前有效输入。
- 不因为用户调整了格式或措辞，就强行恢复旧格式。
- Agent 可以为了保持当前状态准确而修改用户已有条目，但不要为了格式统一进行无意义重写。

条目粒度
- 每个一级列表条目只描述一个 Next Action 或 Open Issue。
- 一个事项包含少量紧密相关信息时，可以使用二级列表。
- 不把多个互不相关的工作塞进一个条目。
- 不把整个会话压缩成一个总结条目。
- 条目脱离原会话后仍应可以理解。
- 优先短句和大纲，不写长篇叙述。

表达规则
- 使用事实性、当前时态表达。
- 优先描述现在是什么，而不是它是如何变成这样的。
- Next Action 应尽量表达明确动作。
- Open Issue 应尽量表达具体未解决问题。
- 保留必要的具体名称、路径、参数、错误信息和版本。
- 区分已确认事实与待验证事项。
- 不补充会话中没有出现、代码或正式文档中也无法确认的事实。
- 不根据常识擅自修正用户已经明确形成的结论。
- 删除无意义的解释性语言和会话式表达。

默认格式
优先沿用已有 FORGET.md 的大纲格式。

文档不存在时使用：

```markdown
# Forget

## Next Actions

- [NEXT] ...

## Open Issues

- [ISSUE] ...
```

没有对应内容的章节可以省略。

允许使用简单二级列表：

```markdown
## Next Actions

- [NEXT] ...
  - ...
  - ...

## Open Issues

- [ISSUE] ...
  - ...
```

不要创建以下独立章节：
- Current State
- Decisions
- Constraints
- Risks
- Questions
- Facts
- Required Facts
- History
- Completed
- Rejected
- Deprecated
- Previous

这些信息如果仍然必要，应附属于某个 Next Action 或 Open Issue。

简短性检查
生成最终文档前，逐条检查：
1. 这个事项当前是否仍未完成？
2. 它是否需要跨会话继续？
3. 不知道这条信息是否会妨碍下一会话继续工作？
4. 是否可以直接从代码或正式文档轻松获得？
5. 是否只是历史、解释、完成记录或讨论过程？
6. 是否存在更短但仍然完整的表达？

如果一个条目不满足继续工作的必要性，应删除。

如果属于可以轻松恢复的信息、历史信息或解释过程，默认删除。

最后再检查所有子条目：
- 是否仍有活跃事项依赖它。
- 是否可以删除而不影响继续工作。
- 是否已经成为孤立信息。

完成条件
- 已遍历当前会话完整历史。
- 已读取并理解现有 FORGET.md，如果存在。
- 用户明确提供的下一步工作范围已被优先采用。
- 用户未提供下一步工作时，已合理推导最可能的 Next Actions。
- 当前仍需继续的 Next Actions 已保留。
- 当前仍需处理的 Open Issues 已自动识别并保留。
- 继续这些事项所需的最小上下文已保留。
- 新事项已添加。
- 状态变化已直接更新。
- 重复或重叠事项已合并。
- 已完成、取消、失效和被取代事项已删除。
- 已删除事项的无用附属信息已同步删除。
- 没有保留完成记录、墓碑信息或历史回顾。
- 没有把正式项目文档可以承担的信息无意义复制进 FORGET.md。
- 文档保持简短的大纲式 Markdown，可直接手工编辑。
- 如果没有需要续接的事项，FORGET.md 已删除。
- 未执行会话切换、Git 提交或其他超出交接文档范围的操作。
