# Life

life 是**一个人的项目文档 —— 项目是这个人的人生**。

它回答的不是：

> 这次要记什么？

而是：

> 这个人的一生，现在走到哪、定了什么、否决了什么、还欠着什么。

主语是「我」，不是项目、模块或系统。

**它存在的理由，是让 agent 能成为「我」的第二大脑。** agent 有执行能力，但没有记忆、不了解这个人；life 补的就是另一半 —— 一个人自己的文档，正如开发项目时要给 agent 项目文件。缺了它，agent 只可能是工具或同事；有了它，才可能是我自己的延长。

# 为什么叫 life

不叫 `brain`，也不叫 `memo`：那两个词只描述**功能**（一个记东西的地方），把「一辈子」压成了一次查询。

「第二大脑」也不是 life 的名字 —— 第二大脑是 **agent 成了之后的样子**，life 是让它成为那样的输入。把两者的名字对调，判据就会从「主语是我」滑向「内容够多」。

`life` 说的是**视角**：一个人的人生就是一个项目。所以这里记的是这个项目的过程 —— 现在在做什么、定了什么、否决了什么、还欠着什么。

# 它是什么：两层

```text
这次发生的事、我当时的想法、当时的处境        ← 原料（会话、材料、事件）
              ↓ 提炼
方向（我的 intent）· 决定（我的 ADR）· 判据     ← 馏出物（树的主体）
```

**原料可以乱**：可以模糊、可以前后矛盾、可以带时间。它记录「我当时是怎么想的」，不是定论。

**馏出物要少而准**：方向只有一份，决定一条一个，判据要能直接用。它们不是原料的摘抄，是从原料里蒸馏出来的东西。

理念是项目文档，但**结构不学项目文档** —— 没有 `STATUS.md`，没有 `ADR/` 目录；产物按主题并进子文档。但**内容的对应物必须有**：一个项目里最重要的两份文档是 intent 和 ADR，这里也要有它们的人生版。

它是**用户级**的：根目录由 `LIFE_ROOT` 指定，未设置时默认 `~/life`。它不随当前工作目录、仓库或任务变化。

# 它不是什么

- 不是日记（按天排的流水）—— 历史在 `git log`；
- 不是知识库（外部世界的知识不进这里）—— 那个归 `~/notes` 一类的专题资料；
- 不是收藏夹（不是越多越好）—— 二十条每次都被读到，胜过两百条烂在盘上；
- 不是每次会话的记录 —— 记的是这次会话**改变了什么**，不是这次会话**发生了什么**；
- 不是自动的 —— 没有写下的那句话，它不会自己变好。

# 不是工具，也不是同事

三者的差别不在能力，在**关系**：

| 关系 | 它的位置 | 后果 |
|---|---|---|
| **工具** | 执行器，不了解你 | 每次重新交代；做出来的东西对得上任务、对不上你 |
| **同事** | 外部协作者，有自己立场 | 要协商、要体面；读的是交接文档，不是你的手记 |
| **第二大脑** | 「我」的延长 | 用你的判据做决定，不需要说服，也允许留下「我当时判断错了」 |

所以这份文档可以难看：可以写失误、写没想明白、写前后矛盾。它没有外部受众 —— 唯一的读者，是那个要变成你的 agent。

推论：它的错是「不够了解你」，不是「不同意你」。出现分歧时不要争，先去 life 里找判据；找不到判据，那才是真的缺失。

# 边界：与相邻几层

| 层 | 主语 | 记什么 | 谁在用 |
|---|---|---|---|
| **life** | 我 | 我要什么、定过什么、否决过什么、怎么判断 | 按需检索，不自动注入 |
| 项目文档（`intent` / `ADR` / `progress` / `debt`） | 项目、模块、系统 | 这个项目为什么这样、现在做到哪 | 跟着项目走，随仓库存在 |
| `~/notes` 类专题资料 | 外部世界 | 这个领域的资料与结论 | 按主题翻 |
| Agent 的常驻记忆 | 环境与约定 | 每条会话都要成立的事实 | 每次注入 |

项目文档里的 `intent` 和 `ADR`，在这里各有一份人生版：**方向**和**决定**。同一副骨架，主语不同 —— 那边的主语是项目，这边是「我」。

判据不是「跨不跨项目」，而是**主语是谁 + 五年后的我会不会为了理解自己而翻它**。

有项目字眼不算错，它只是场景：`我做过 n1paper，学到的教训是 X` 进 life，`n1paper 的构建命令是 Y` 留在项目里。

# 从会话里提炼什么

**不是筛选，是蒸馏。** 整场会话是原料，要问的是三个问题：

1. **我的方向变了吗** → 有，就更新方向那一页（覆盖旧的，旧版在 git 里）；
2. **有没有做一个关掉一批选项的决定** → 有，就追加一条决定，连同被否决的选项；
3. **有没有形成一条下次能省一次犹豫的判据** → 有，就连同它的来由写进主题。

三种产物都要求**主语是「我」**。

两种提炼失败，方向相反：

- **提炼不足** —— 只留了记录，没有产物。树变成流水账。
- **提炼过度** —— 只留了产物，没有来由。树变成教条，情况变一点就套不上。

明确不进：本次做了什么、调试过程、时间线、只对本次任务有意义的状态、凭据与密钥、别人的私事。它们不是「丢掉」，是留在项目里或会话里。

# 方向（我的 intent）

**只有一份，单独一页。** 改了就覆盖旧的（旧的留在 git），不允许两个版本的方向并存。

装什么：

- 我要什么；
- 冲突时保哪个（优先级）；
- 明确不做什么（非目标）。

一条检验：**读完它，某些方案应该自动出局**。读不出被排除的选项，说明写的还是愿景，不是方向。

允许模糊、允许内部有张力（两个都想要，边界还没想清）—— 但张力要收在同一页里，不要分叉成两份。

分身在读任何主题之前，先读这一页。判据回答「怎么选」，方向回答「为什么选」。

# 决定（我的 ADR）

**一条一个决定，累积，永不合并。**

每条至少四样：

1. 当时的处境（约束是什么）；
2. 摆着的选项；
3. 选了哪个、为什么；
4. **被否决了哪些** —— 只写「我选了 X」等于没记，因为下次会把否决项重新认真考虑一遍。

**被推翻的决定不删**，标成「已推翻」。它本身是后一个决定的来由，删了就看不出为什么会改。

决定的价值不在「我选了什么」，在**它关掉了一整批选项**。

# 判据

**一条可以直接拿出来用的选择规则：遇到某类情形，按它就能做出跟过去一致的决定。**

缺一样就不可用：触发条件（什么情形下用它）、选哪边、理由或失效边界。

两个检验：拿给不知道上下文的人能不能用；下次遇到能不能省一次犹豫。

**有效期不是时间，是反例** —— 它导致一次错判就该改，不会放着变对。

强弱：强判据无条件（「凭据绝不写进这里」）；弱判据带边界（「这类事偏保守，除非……」）；还有按情形拆的（「小改动偏快、容忍返工；不可逆的偏稳」）。

# 来由：留多少

产物和原料之间要留一段来由。判据没有它不可迁移，决定没有它不可理解。

两条检验：

1. 压缩后的文本，能不能**重新推导**出这个结论；
2. 能不能据此判断**新情形算不算同一类**。

都过 → 留够了。只能过第一条 → 是教条，记得结论不知边界。

留什么：当时的约束、当时的预期、错在哪（**没有误判，判据就不成立**）。
丢什么：时间线、步骤、谁说了什么。

# 状态的写法

- **正文是当前状态，不是时间线**。任何时刻读它，读到的都是「我现在相信什么」；条目上的日期是这条**最近一次确认的时间**，不是事件发生的时间。
- **张力要收在一条里**。模糊、两难都是真实状态，必须记，并标为不确定 —— 不记它等于假装确定，agent 会拿旧的确定冒充现在的你。两种情形下各成立的说法写进同一条、各自带上条件；只有同一情形两个相反说法且无条件区分，才是漂移（bug），必须合并。
- **「一条说法」只约束状态类**（方向、倾向、当前做法）。决定是事件：两条决定并存正常，被推翻的标记而不删。
- 新建子文档的门槛只有一条：**它会被独立检索**。不满足就并进最接近的已有文件。

# 内部形态

```text
<LIFE_ROOT，默认 ~/life>/
├── README.md    入口：方向入口 + 索引 + 规矩
├── <主题>.md    子文档（活文档，不带日期）
├── refer/       原始材料快照（带日期）
├── hits.md      装载痕迹（非文档，只供分析）
└── archive/     已移出检索范围的内容（不读）
```

方向独占一页，在入口索引里放在第一区；决定和判据按主题并进子文档。

# 这个 Skill 不做的事

本 Skill 只定义概念，不执行任何动作。装配、读取、写入分别归：

| Skill | 职责 |
|---|---|
| `life-init` | 装配：根目录、入口 README、git 仓库、私有远端、每日定时推送（仅限用户显式调用） |
| `life-load` | 读取：检查树状态 + 按目标检索最小必要的那几节（只读） |
| `life-save` | 写入：提炼 → 查现状 → 归类 → 并进子文档 → 同步入口 → 本地提交（唯一写者） |

拿不准这次提炼出了什么、要解释 life 与项目文档的区别，用本 Skill 回答；要动树，用上面三个。

# 核心原则

> **life 是一个人的项目文档：主语是「我」；从经历里蒸馏出方向、决定与判据，并留下刚好够的来由 —— 判据是五年后的我会不会为了理解自己而翻它。**
