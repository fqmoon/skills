# Life Load

第二大脑的**读取器**。两件事：

| 功能 | 回答 |
|---|---|
| **检查** | 这棵树现在是什么状态？有没有错？ |
| **检索** | 关于这件事，我此前已经判过什么？ |

它**不改资料**：不新增、不修改、不删除。发现的问题**只报告** —— 修是 `life-save` 的事。

唯一的写入是一次可选的装载痕迹。

**这棵树是什么：** 你的判据集，主体是你 —— 而且是上位层：项目资料也在内（一个项目就是你人生里的一段）。装载它是在恢复**你此前怎么判**，不是查资料库。

# 资料树

```text
$LIFE_ROOT（默认 ~/life）
├── README.md             入口：立意 + 规矩 + 索引
├── <主题>.md             子文档（活文档，不带日期）
├── refer/                原始材料快照（带日期）
├── hits.md               装载痕迹（可选，非文档）
└── archive/              已移出检索范围（**不读**）
```

**它是用户级的，不随工作目录变化。** 每次装载说明本次用的哪个根目录、是 `LIFE_ROOT` 指定还是默认。

根目录或入口不存在 → **直接说树不存在，不要静默跳过**；建树属于 `life-init`。

# 什么时候装载

- 用户给出一个目标，而这件事可能此前判过；
- 当前判断依赖此前的结论、判据或约定；
- 用户明确要求回顾。

首次接触、且与既有积累无关的任务上，不要机械装载。

# 检查什么

| 检查项 | 不对的表现 |
|---|---|
| 入口 ↔ 文件对得上 | 登记了不存在的文件；存在文件没登记 |
| **不是日记** | 正文里出现按时间排的流水（「11-07 …，11-08 …」）|
| 没有墓碑 | 正文还留着「曾经认为 X」「已废弃」 |
| 状态不打架 | 同一件事在正文里有两处不同说法 |
| 最近变化没失控 | 超过 5 条 |
| 子主题没臃肿 | 某个二级标题下超过约 10 条 |
| `refer/` 没有孤儿 | 有文件没被任何条目引用 |
| `hits.md` 没有孤儿行 | 有行指向已不存在的文件 |
| **git 没积压** | 有未提交改动，或 `git status` 不干净 —— **报告，不提交** |

检查结果怎么处置：

- **独立调用**（会话开头、用户手动）→ 报给用户；
- **被 `life-save` 调用** → 索引类问题它顺手修；改结论 / 删这类要确认的，进它那份清单。

# 两级读取

**不要一次读完整个树。**

```text
1. 读入口 README
   → 索引里哪一行与当前目标相关
2. 命中的子文档
   → 先看目录，只取相关小节
```

入口索引不足以判断相关性时，才降级为全文检索。

`refer/` 不列在入口 —— 它的入口是子文档里的链接。`archive/` **完全不读**。

# 查历史（演变在 git 里）

正文是当前状态，**时间线只在 git 里** —— 想知道「这条为什么变成现在这样」，翻历史：

```bash
git -C ~/life log --oneline -20          # 主题列表，一句一条
git -C ~/life log -p -- <文件>           # 某文件的逐次改动
git -C ~/life show <sha>                 # 某次的完整说明
```

消息第一行是主题、其后分条，所以 `--oneline` 就能扫完最近发生了什么。**别去正文里找时间线**（规矩 5 禁止它）。

# 装多少

装载量是成本。

- 只装当前判断确实需要的部分；
- 同一小节反复被用到 → 它该被提炼进入口或独立成节，而不是每次重读；
- 装完说明装了哪几个文件的哪几节。

# 装载痕迹（可选）

`hits.md` 里原地更新一行：

```text
第二大脑.md     last 2026-11-07    hits 12
```

- 文件不在就新增一行；`hits.md` 不存在时**不强制创建**；
- **它不驱动任何决策**，纯观测；写失败不阻断装载；
- 它量的是**入口描述**写得好不好（某文件从没被读 → 多半是入口那行写歪了），不是内容质量。

**这一项是次要指标** —— 这棵树优化的不是索引质量，是判据的命中率。别为了这份痕迹多花一步。

# 装载不等于采信

资料是此前得出的结论，不是当前事实。

- 日期新近且未被推翻 → 可直接采用；
- 涉及代码、配置、环境的结论 → 仍需回现场核对；
- 资料与现场冲突 → **暴露冲突，不要静默选一边**。

# 不负责

- 不改资料内容；不做结构调整（检查出来交回 `life-save`）；
- 不提交 git，不删 `archive/`；
- 不用检索结果代替现场调查。

# 核心原则

> **检查现状 + 按目标检索最小必要的那几节 —— 只读，不改资料。**
