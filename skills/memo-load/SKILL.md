# Memo Load

从 memo 资料树中，按当前目标装载相关的既有结论。

它回答的是：

> 关于这件事，此前已经得出过什么？

它不新增内容，也不修改资料。

# 资料树

```text
~/memo/                   ← MEMO_ROOT，未设置时默认此处
├── README.md             入口：索引 + 规矩
├── <主题>.md             子文档（活文档，不带日期）
├── refer/                原始材料快照（带日期）
├── hits.md               装载痕迹（非文档）
└── archive/              已不再增长的子文档
```

根目录由 `MEMO_ROOT` 指定，未设置时默认 `~/memo`。

**它是用户级的，不随当前工作目录变化。** 每次装载都应说明本次使用的是哪个根目录、是指定还是默认。

根目录或入口 README 不存在时，**直接说明资料树不存在，不要静默跳过** —— 建树属于 `memo-save`。

# 什么时候装载

- 用户给出一个目标，而这件事可能此前做过；
- 当前判断依赖此前得出的结论、判据或约定；
- 用户明确要求回顾此前的工作。

不要在明显是首次接触、且与既有积累无关的任务上机械装载。

# 两级读取

**不要一次读完整个资料树。**

```text
1. 读入口 README
   → 索引里哪一行与当前目标相关
2. 命中的子文档
   → 先看它的目录，只取相关小节
```

只有当入口索引不足以判断相关性时，才降级为在子文档中检索。

`refer/` 不逐条列在入口里 —— 它的入口是子文档条目里的链接，按需顺着链接取。

# 装多少

装载量是成本，不是越全越好。

- 只装当前判断确实需要的部分；
- 同一小节反复被用到时，说明它该被提炼进入口或独立成节，而不是每次重读；
- 装载完成后，说明装了哪几个文件的哪几节。

# 装载痕迹

装载完成后，**原地更新** `hits.md` 里对应那一行：

```text
agent-tooling.md     last 2026-11-05    hits 12
```

- 文件不存在时创建；文件不在表里时新增一行；
- **这是本 Skill 唯一的写入**；
- 目的是给 `memo-maintain` 提供「哪几篇其实没人读」的证据 —— 没有它，归档判据无从判断；
- **命中 = 被装载进上下文**，不要求「被采用」：归档判的是「还有没有人读」，不是「还有没有用」；
- `hits.md` 不是 memo 文档：不进入口索引，也不参与内容检索；
- 装载失败时不留痕；**写痕迹失败不阻断装载** —— 痕迹是次要的，装载是主要的，失败时说明一下即可。

# 装载不等于采信

资料是此前得出的结论，不是当前事实。

- 带日期的条目：日期新近且未被推翻时，可直接采用；
- 涉及代码、配置、环境状态的结论，仍需回到现场核对；
- 资料与现场冲突时，暴露冲突，不要静默选一边。

# 不负责

- 不修改资料内容（新增与改写属于 `memo-save`）；
- 不做全局整理（属于 `memo-maintain`）；
- 不用装载结果代替现场调查。

# 核心原则

> **按目标装载最小必要的那几节；留一行痕迹，因为「没人读」是归档的唯一依据。**
