# Memo Load

memo 资料树的**读取器** —— 它做三件事：

| 功能 | 回答 |
|---|---|
| **检查** | 这棵树现在是什么状态？有没有错？ |
| **检索** | 关于这件事，此前已经得出过什么？ |
| **看变化** | 上次之后，树里改了什么？ |

它**不写任何东西**：不新增、不修改、不删除。发现的问题**只报告** —— 修是 `memo-save` 的事。

`memo-save` 在写入前会调用它。**写之前必须先看现状，这一步不能靠记忆。**

**这棵树是 agent 自己的缓存，不是给人的文档。** 读者是下一个进程里空上下文的自己 —— 所以我在这里唯一要做对的事是：**判断这些结论现在还算不算数。**

# 资料树

```text
~/memo/                   ← MEMO_ROOT，未设置时默认此处
├── .git/                 ← 本地仓库（无远端），提供 diff
├── <主题>.md             子文档（活文档，不带日期）；frontmatter 带关键字
└── refer/                原始材料快照（带日期）
```

根目录由 `MEMO_ROOT` 指定，未设置时默认 `~/memo`。

**它是用户级的，不随当前工作目录变化。** 每次装载都应说明本次用的是哪个根目录、是指定还是默认。

**树里只有数据** —— 没有入口 README、没有归档。规矩与目录语义写在 Skill 里。

根目录不存在时，**直接说明资料树不存在，不要静默跳过** —— 建树属于 `memo-save`。

# 什么时候装载

- 用户给出一个目标，而这件事可能此前做过；
- 当前判断依赖此前得出的结论、判据或约定；
- 用户明确要求回顾此前的工作。

不要在明显是首次接触、且与既有积累无关的任务上机械装载。

# 检索

**不要一次读完整个资料树。**

```text
1. ls 根目录
   → 树里有哪些主题
2. grep 关键字
   → 哪个文件对得上
3. 打开命中的文件
   → 先看它的 H2，只取相关小节
4. git log / git diff
   → 这几节最近变过什么
```

第 2 步一条命令就能拿到整棵树的索引：

```bash
grep -rn '^keywords:\|^says:' ~/memo --include=*.md
```

- `keywords` 是字面词：域名、配置键、命令、错误码、主题名词；
- `says` 是**那句话会怎么被问出口**：症状、口头说法、旧名与别名 —— 这一层 grep 自己猜不到。

只有当关键字都对不上时，才降级为在正文里 grep。

`refer/` 不单独列出来 —— 它的入口是子文档条目里的链接，按需顺着链接取。

# 看变化

**读文件之前先看一眼 log** —— 我不记得上次来是什么状态，git 记得。

```bash
git -C ~/memo log --oneline -5
git -C ~/memo diff HEAD~1 --stat
```

用处有两处，都比「能回滚」更重要：

- **知道最近哪几节被改过**：改过的条目最可能过期，优先核对；
- **知道结论被推翻过**：diff 里看得见旧版本长什么样，而不只是新版本。

# 报告：只说它改变了什么

**装载完只用一到两句，说「这条笔记让我哪件事做得不一样」。**

```text
✅ 部署那条写着口令已改由 Access 托管（11-06），所以这次不碰 nginx 口令。
❌ 读到了 cloudflare-配置.md 和「隧道」一节，里面说……   ← 这是重述，等于没装载
```

判据：**纯转述 = 没装载。** 复述里必须出现原文没有的东西 —— 也就是「所以我接下来要怎么做」。

**不确定的地方用「动作被卡住」来表达**，不用「知识有缺口」：「这个配置我不敢动，因为两条记录冲突」是装载；「我了解到这里有冲突」不是。

**不要为了显得读过而把内容搬一遍。** 「要求复述」天然激励重述，这是这个动作最大的坑：说「我了解到」没有代价，说「所以我要做 X」会被后面的事实验证。

**没命中也要说一句「memo 无相关」。** 沉默分不清「没搜到」和「搜到但没用上」，而这棵树唯一的验收就是这两者的比例 —— 长期都是「无相关」，说明它在空转。

# 装多少

装载量是成本，不是越全越好。

- 只装当前判断确实需要的部分；
- 同一小节反复被用到时，说明它该独立成节或拆成新文件，而不是每次重读；
- 装载完成后，按上一节的说法一句话交代，不复述内容。

# 装载不等于采信

**这是本 Skill 的核心，不是脚注。** 资料是此前得出的结论，不是当前事实。

- 带日期的条目：日期新近、且没进过 diff 的，可直接采用；
- 每条结论都带**锚**（路径 / 符号名 / 命令 / URL）—— 涉及代码、配置、环境状态的，**用锚回现场核对**；锚核不到的按未验证处理；
- 资料与现场冲突时，**以现场为准**，并暴露冲突。冲突本身就说明该改写了 —— 那是 `memo-save` 的事。

没有锚的旧条目：可以用，但要在复述里说明它是无锚结论。

# 检查什么

顺带过一遍，**问题只报告，不修**：

| 检查项 | 不对的表现 |
|---|---|
| 没有墓碑 | 正文里还留着「曾经认为 X」「已废弃」这类被推翻的记录 |
| 子主题没臃肿 | 某个二级标题下超过约 10 条 |
| `refer/` 没有孤儿 | 有文件没被任何条目引用 |
| 有关键字 | frontmatter 缺 `keywords` / `says`；或只有主题词，没有「那句话会怎么被问出口」 |
| 有锚 | 结论没带可回现场的锚 |

检查出来直接交给 `memo-save` 处理 —— 它现在是自动的，不需要人点头。

# 不负责

- 不写盘（新增、改写与删除属于 `memo-save`）；
- 不做全局整理与结构调整（**检查出来交回 `memo-save`**）；
- 不用检索结果代替现场调查；
- 不因为「想让用户知道自己读过」而展开内容。

# 核心原则

> **按目标检索最小必要的那几节、顺手看 diff、用锚核对 —— 只说结论改变了什么。**
