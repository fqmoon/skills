# Memo Load

memo 资料树的**读取器** —— 它做两件事：

| 功能 | 回答 |
|---|---|
| **检查** | 这棵树现在是什么状态？有没有错？ |
| **检索** | 关于这件事，此前已经得出过什么？ |

它**不写任何东西**：不新增、不修改、不删除。发现的问题**只报告** —— 修是 `memo-save` 的事。

`memo-save` 在写入前会调用它。**写之前必须先看现状，这一步不能靠记忆。**

# 资料树

```text
~/memo/                   ← MEMO_ROOT，未设置时默认此处
├── <主题>.md             子文档（活文档，不带日期）；frontmatter 带关键字
└── refer/                原始材料快照（带日期）
```

根目录由 `MEMO_ROOT` 指定，未设置时默认 `~/memo`。

**它是用户级的，不随当前工作目录变化。** 每次装载都应说明本次使用的是哪个根目录、是指定还是默认。

**树里只有数据** —— 没有入口 README、没有归档。规矩与目录语义写在 Skill 里，跟着 Skill 走。

根目录不存在时，**直接说明资料树不存在，不要静默跳过** —— 建树属于 `memo-save`。

# 什么时候装载

- 用户给出一个目标，而这件事可能此前做过；
- 当前判断依赖此前得出的结论、判据或约定；
- 用户明确要求回顾此前的工作。

不要在明显是首次接触、且与既有积累无关的任务上机械装载。

# 检查什么

每次读取顺带检查一遍。**问题只报告，不修**：

| 检查项 | 不对的表现 |
|---|---|
| 没有墓碑 | 正文里还留着「曾经认为 X」「已废弃」这类被推翻的记录 |
| 子主题没臃肿 | 某个二级标题下超过约 10 条 |
| `refer/` 没有孤儿 | 有文件没被任何条目引用 |
| 有关键字 | frontmatter 缺 `keywords` / `says`；或只有主题词，没有「你会怎么说」 |

检查结果怎么处置，看是谁在调用：

- **独立调用**（会话开头、你手动）→ 报给你；
- **被 `memo-save` 调用** → 进它那份待确认清单。

# 检索

**不要一次读完整个资料树。**

```text
1. ls 根目录
   → 树里有哪些主题
2. grep 关键字
   → 哪个文件对得上
3. 打开命中的文件
   → 先看它的 H2，只取相关小节
```

第 2 步一条命令就能拿到整棵树的索引：

```bash
grep -rn '^keywords:\|^says:' ~/memo --include=*.md
```

- `keywords` 是字面词：域名、配置键、命令、错误码、主题名词；
- `says` 是**你会怎么说**：症状、口头说法、旧名与别名 —— 这一层 grep 自己猜不到，只能靠它被写下来。

只有当关键字都对不上时，才降级为在正文里 grep。

`refer/` 不单独列出来 —— 它的入口是子文档条目里的链接，按需顺着链接取。

# 装多少

装载量是成本，不是越全越好。

- 只装当前判断确实需要的部分；
- 同一小节反复被用到时，说明它该独立成节或拆成新文件，而不是每次重读；
- 装载完成后，说明装了哪几个文件的哪几节。

# 装载不等于采信

资料是此前得出的结论，不是当前事实。

- 带日期的条目：日期新近且未被推翻时，可直接采用；
- 涉及代码、配置、环境状态的结论，仍需回到现场核对；
- 资料与现场冲突时，暴露冲突，不要静默选一边。

# 不负责

- 不写盘（新增、改写与删除属于 `memo-save`）；
- 不做全局整理与结构调整（**检查出来交回 `memo-save`**）；
- 不用检索结果代替现场调查。

# 核心原则

> **检查现状 + 按目标检索最小必要的那几节 —— 只读、不写。**
