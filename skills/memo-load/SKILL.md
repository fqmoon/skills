# Memo Load

memo 资料树的**读取器** —— 它做两件事：

| 功能 | 回答 |
|---|---|
| **检查** | 这棵树现在是什么状态？有没有错？ |
| **检索** | 关于这件事，此前已经得出过什么？ |

它**不改资料**：不新增、不修改、不删除。发现的问题**只报告** —— 修是 `memo-save` 的事。

唯一的写入是 `hits.md` 里的一行装载痕迹（见下）。

`memo-save` 在写入前会调用它。**写之前必须先看现状，这一步不能靠记忆。**

# 资料树

```text
~/memo/                   ← MEMO_ROOT，未设置时默认此处
├── README.md             入口：索引 + 规矩
├── <主题>.md             子文档（活文档，不带日期）
├── refer/                原始材料快照（带日期）
├── hits.md               装载痕迹（非文档，只供分析）
└── archive/              已移出检索范围的内容（**不读**）
```

根目录由 `MEMO_ROOT` 指定，未设置时默认 `~/memo`。

**它是用户级的，不随当前工作目录变化。** 每次装载都应说明本次使用的是哪个根目录、是指定还是默认。

根目录或入口 README 不存在时，**直接说明资料树不存在，不要静默跳过** —— 建树属于 `memo-save`。

# 什么时候装载

- 用户给出一个目标，而这件事可能此前做过；
- 当前判断依赖此前得出的结论、判据或约定；
- 用户明确要求回顾此前的工作。

不要在明显是首次接触、且与既有积累无关的任务上机械装载。

# 检查什么

每次读取顺带检查一遍。**问题只报告，不修**：

| 检查项 | 不对的表现 |
|---|---|
| 入口 ↔ 文件对得上 | 入口登记了不存在的文件；存在文件没登记 |
| 没有墓碑 | 正文里还留着「曾经认为 X」「已废弃」这类被推翻的记录 |
| 最近变化没失控 | 超过 5 条 |
| 子主题没臃肿 | 某个二级标题下超过约 10 条 |
| `refer/` 没有孤儿 | 有文件没被任何条目引用 |
| `hits.md` 没有孤儿行 | 有行指向已不存在的文件 |

检查结果怎么处置，看是谁在调用：

- **独立调用**（会话开头、你手动）→ 报给你；
- **被 `memo-save` 调用** → 索引类的问题它顺手修；改结论 / 删这类要先问的，进它那份清单。

# 两级读取

**不要一次读完整个资料树。**

```text
1. 读入口 README
   → 索引里哪一行与当前目标相关
2. 命中的子文档
   → 先看它的目录，只取相关小节
```

只有当入口索引不足以判断相关性时，才降级为在子文档中检索。

`refer/` 不逐条列在入口里 —— 它的入口是子文档条目里的链接，按需顺着链接取。

**`archive/` 完全不读** —— 它在检索范围之外。那是「不删，但也不再指望」的东西；只有你明确要翻历史时才去看。

# 装多少

装载量是成本，不是越全越好。

- 只装当前判断确实需要的部分；
- 同一小节反复被用到时，说明它该被提炼进入口或独立成节，而不是每次重读；
- 装载完成后，说明装了哪几个文件的哪几节。

# 装载痕迹

装载完成后，**原地更新** `hits.md` 里对应那一行：

```text
agent-tooling.md     last 2026-11-05    hits 12
```

- 文件不存在时创建；文件不在表里时新增一行；
- **这是本 Skill 唯一的写入**；
- **它不驱动任何自动决策** —— 纯观测数据，给人看。所以「写失败」的代价可以接受：**写痕迹失败不阻断装载**，说明一下即可；
- `hits.md` 不是 memo 文档：不进入口索引，也不参与内容检索。

**它用来分析什么：入口描述写得好不好。**

一个文件被不被读到，只取决于入口那一行的描述能不能被目标对上 —— 所以这份痕迹量的是**入口**，不是内容。

| 看到什么 | 说明什么 |
|---|---|
| 某文件从没被读过 | 多半不是它没用，是**入口那一行写歪了**，目标对不上 |
| 某文件被反复读 | 多半是**入口那一行描述不够准**，每次都得翻进去确认 |
| 总命中数长期很低 | 要么入口写歪了，要么这棵树没在用 —— 正是需要知道的事 |

# 装载不等于采信

资料是此前得出的结论，不是当前事实。

- 带日期的条目：日期新近且未被推翻时，可直接采用；
- 涉及代码、配置、环境状态的结论，仍需回到现场核对；
- 资料与现场冲突时，暴露冲突，不要静默选一边。

# 不负责

- 不修改资料内容（新增、改写与删除属于 `memo-save`）；
- 不做全局整理与结构调整（**检查出来交回 `memo-save`**）；
- 不用检索结果代替现场调查。

# 核心原则

> **检查现状 + 按目标检索最小必要的那几节 —— 只读、不改资料，只留一行痕迹。**
