# 用户隐私与敏感信息

快照可能是私人产物，不默认上传公共仓库。包含身份或机器信息不是一律禁止的，但必须明确提醒，不能默认产物适合分享。

## 信息分类

- **普通环境信息**：系统版本、软件版本、通用配置与非敏感偏好，通常可以直接记录。
- **身份与机器信息**：姓名、邮箱、用户名、主机名、绝对路径、IP、内部域名、设备标识、私有服务地址等。它们可能是还原所需材料，也可能暴露个人或组织信息。
- **凭据与秘密**：密码、token、API key、私钥、cookie、session、内嵌认证信息等。不能与普通环境信息等同处理。

分类依上下文判断：某项信息单独看似普通，组合后也可能识别用户、设备或组织。

## 采集

只调查任务相关的信息，不因为能够读取就遍历认证目录、历史记录或日志。配置可能混有秘密，读取前先判断范围，尽量使用不会直接输出秘密值的检查方式。

发现敏感内容后，不在终端输出、对话、差异报告或其他说明中重复秘密值。报告信息类别与位置即可。

## 写入快照

身份与机器信息可以因用户目的而保留；写入时明确提醒其类别、用途与分享风险。无还原价值的信息不要为完整性额外收录。

可以用相对路径、变量或占位符降低暴露，但不要静默脱敏导致配置失效。说明省略或替换了哪些类别、还原时如何补充；无法判断是否应保留时询问用户。

凭据不默认纳入快照。若确实需要包含，先取得针对秘密类别和保存位置的明确确认，并说明泄漏后果、保存与分享风险。一般性的“保存我的环境”不等于授权复制全部认证材料。

不要将现场身份信息或秘密写入公共 Skill 文档。用户快照与 Skill 本身是不同的产物与分享边界。

## 分享、上传与提交

生成或更新快照不等于授权对外分享，也不等于授权 Git 暂存或提交。

用户要求分享、上传或提交前，检查将要发布的全部材料，包括文件名、隐藏文件、配置、脚本与描述。若发布包含历史，也要考虑历史中残留的敏感信息。

同时检查常见凭据模式与身份、机器信息；不能只检查本次修改。检查结果以文件、位置和信息类别报告，不展示秘密值。说明检查范围与局限，未命中不代表绝对安全。

发现敏感信息时，在发布前明确提醒并等待处理决定。涉及凭据时建议移除、替换或采用独立的秘密管理方式；已经泄漏的凭据需要撤销或轮换，删除文件不能消除泄漏。

## 报告

简要说明保留了哪些敏感信息类别，哪些被省略、替换或尚待确认，以及分享前仍需处理的风险。不要以“这是私人快照”为由省略提醒。
