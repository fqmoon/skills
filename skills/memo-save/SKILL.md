# Memo Save

把这段工作里值得长期留下的结论，写进 memo 资料树。

**它不只在收尾时跑。** 阶段边界就是写入点 —— 收尾只是其中一种边界。

**它不是「存一下」。** 完整动作是：

```text
提炼 → 查现状（调 memo-load）→ 归类 → 列清单确认 → 写 → 回一句
```

**第二步不能省，也不能靠记忆。** 写之前必须先看树里现在是什么状态：目标文件里已经有什么、该并入哪一节、有没有要改写的旧结论、有没有要顺手修的错误。

不查现状就写，会写出重复条目；只提炼不归类，文件会越开越多。

**它是这棵树唯一的写者** —— 写入和维护都归它。

# 它是交互 skill

**新增、改、删都要先问。一次列清单，一次问。**

| 动作 | 为什么 |
|---|---|
| **新增** | 错结论会成为下次的前提 —— 事后审计不如事前过一眼 |
| **改**（改写被推翻的结论） | 破坏性 —— 旧的那句会消失 |
| **删** | 破坏性 —— 同上 |

清单里逐条写清：动哪个文件、哪一节、做什么、动完是什么样。多处一起动时合并成一份，不要一条一问。

**确认后一次写完，只回一句「已按清单写入」** —— 清单本身就是汇报，不要再复述一遍。

# 建树

**两个 Skill 里只有 `memo-save` 写盘**（`memo-load` 只读）。根目录不存在时创建：

```text
~/memo/
└── refer/
```

树里不放 README：**规矩跟着 Skill 走，数据只管数据。**

# 提炼什么

一条信息值得留下，当且仅当同时满足：

1. **它是结论**，不是过程；
2. **下次做同类事会用到**。

按这两条筛，通常只留下：

- 判据（以后怎么选）；
- 结论及其边界条件（什么情况下成立）；
- 踩过的坑（为什么不能那样做）；
- 约定（此后必须遵守的）。

明确不留下：本次做了什么、调试过程、已完成事项、只对本次任务有意义的状态。

**绝不能留下**：凭据与密钥、别人的私事 —— 任何「删掉会比留着便宜」的东西。

这一条比上面两条更硬。上面判断错了只是噪音，这里判断错了是**留在盘上的债**。

# 归类

**先找已有的子文档** —— 这一步由 `memo-load` 给出（`ls` 到的文件名），不要靠自己回忆。**不要急着新建**，按主题匹配，不按本次任务匹配。

新建子文档的门槛只有一条：

> **它会被独立检索** —— 有人可能只想找这一件事。

不满足就并进最接近的已有文件。

命名：

- **不带日期** —— 子文档是活文档，会被改写；
- 用**一年后还在的词**，不用当前这件事的词；
- 名词短语，用你会说出口的词；
- 文件名只帮人扫读，**不承担检索** —— 检索靠 frontmatter。

# 关键字（frontmatter）

每个子文档开头必须有这两行：

```markdown
---
keywords: 部署, 隧道, Access, 口令, pipipi.fqmoon.cc
says: 那个网站打不开, 登不上了, 怎么又要口令
---

# <主题>
```

| 字段 | 放什么 | 为什么需要 |
|---|---|---|
| `keywords` | 字面词：域名、配置键、命令、错误码、主题名词 | grep 得得到，但需要有人写下来 |
| `says` | **你会怎么问**：症状、口头说法、旧名与别名 | grep **自己猜不到** —— 不写就永远搜不到 |

**三条硬规矩**：

1. **只放词与短说法，不放句子、不放结论** —— 写成摘要就会漂，旧入口就是这么坏的；
2. **一行一个字段，约 10 个以内**，逗号分隔；值里不要出现冒号（会坏 YAML）；
3. **两种词都要有** —— 只有主题词等于只做了一半。

文件名里已经有的词不必重复。新增文件必须带这两行；后续出现新的常用说法，补进 `says`（算写盘，进清单）。

# 写成什么样

条目 = **一句结论 + 日期**。（文件头的 frontmatter 见上一节）

```markdown
## <子主题>

- 结论内容。 (2026-11-05)
- 结论内容。 (2026-11-05)
  - 只在下次会用到时，才补最多两三条细节。
```

- 二级标题就是子主题，也是检索单位 —— 标题要能被目标对上；
- **日期必留** —— 它是判断新鲜度的**唯一**依据。**所有条目一视同仁**：不区分内容类型、不预判谁会过期，新鲜度只看这一个数；
- 不写叙述，不写「本次讨论了」。

# 原始材料放 refer/

默认**只放链接**，不复制内容：

```markdown
- 结论内容。 (2026-11-05)
  - 来源：<绝对路径 或 URL>（取自 2026-11-05）
```

只有**用户明确指定要存**时，才把材料复制进 `refer/`：

- **带日期**命名 —— 与子文档相反，因为它是快照、不改写；
- 文件开头自带来源信息：从哪来、什么时候取的；
- 子文档里指向它，而不是把内容摊进子文档。

判据与 `myenv` 一致：**Skill 自己判断不构成复制授权。**

# 只留当前有效结论

被推翻的结论**直接改写成新的**，不留墓碑：

```text
不要：曾经认为 X，后来改为 Y。
要：  Y。
```

保留日期即可，不需要保留 X。

# 删除

**这棵树没有归档。** 对一条要动的内容，只有两条路：

| 情形 | 做什么 |
|---|---|
| **不该存在**（凭据、私事、错贴、噪音） | **删** —— 它是事实，删掉比留着便宜 |
| 被推翻，但有替代结论 | **改写** —— 内容还有效，只是换了形态 |
| **没用了** | **不是删除理由** —— 得你明确说删才删 |

「没用了」是判断，判断不由 Skill 下。你说了删，就删；你不说，它留着。

## 动干净清单

**先分清动的是哪一层** —— 层级错了会动到不该动的：

| 动什么 | 删 |
|---|---|
| **条目**（一个 H2 / 一条） | 删条目；若它代表那个文件的主要内容，顺带检查文件名是否还成立 |
| **文件**（最后一个条目处理完后） | 删文件 + 只删**没有被引用的** refer 快照 |
| **refer 快照** | 只在确认没有子文档引用时才删（一份可能被多条引用） |

# 什么时候写

**不是只在收尾。** 两个触发面：

| 触发面 | 例子 | 为什么是这里 |
|---|---|---|
| **阶段边界** | 一个判断被推翻、一个方案定下来、踩到一个会再踩的坑、交付了一样东西 | 会话可能走不到「收尾」；等到收尾，当时的判据已经凉了，只剩结果 |
| **收尾** | 任务完成、用户说告一段落 | 把还挂着的待定项清掉 |

**粒度**：一次阶段边界 = 一次清单 = 一次确认。不要每条洞察都停一下，也**不要全攒到最后** —— 攒到最后写出来的往往是「这次做了什么」，而不是结论。

待定项在阶段边界就清空；没清完的，跟着收尾那份清单一起问。

# 维护（顺手做的结构调整）

**维护归本 Skill。** 这几件事**看到就做**，不攒着：

| 看到什么 | 做什么 |
|---|---|
| 某个二级标题下超过约 10 条 | **拆成独立子文档** |
| 两个子文档其实讲同一件事 | **并为一个** —— 用更宽的那个文件名 |
| 文件名已经对不上内容 | **改名** —— 只影响人眼扫读 |
| 出现新的常用说法 / 别名 | **补进该文件的 `says`** |
| `refer/` 里有没被任何条目引用的文件 | **报告，不删**（可能是你手动放的） |

它们是**改结构**，不是改结论 —— 但一样要**先问**（都不可逆）。

# 不负责

- **不做「定期通读整棵树」的巡检** —— 树的健康靠两件事维持：每次写前看现状，以及那份待确认清单。代价是**漂移没有兜底** —— 哪次忘了归类，就要等下次有人碰那个文件才发现；
- 不记录任务进度。判据是：**下次做同类事会用到 → 这里；下次接着做这件事 → `progress` / 项目的 Execution Plan**；
- 不写入当前有效结论之外的历史。

# 核心原则

> **提炼出结论、并进对的文件、写前看现状；只留当前有效版本。**
