# Memo Save

把这段工作里值得长期留下的结论，写进 memo 资料树，然后 commit。

**它是 agent 自己的笔记，不是写给人看的文档。** 读者是下一次的我：一个新进程、空上下文，只知道当前任务。所以「完整」不是美德，**可检索、可核对、会改变动作**才是。人读到噪音只损失十分钟还能跳过；我会连噪音一起当前提用。

**它不只在收尾时跑。** 阶段边界就是写入点 —— 收尾只是其中一种边界。

**它不是「存一下」。** 完整动作是：

```text
提炼 → 查现状（调 memo-load）→ 归类 → 写 → git commit
```

**第二步不能省，也不能靠记忆。** 全自动写入最大的风险不是写错，是**记到了找不到的地方** —— 而「搜不到」不产生任何反馈。写前看一遍现状，是唯一能挡住这种静默失败的动作。

不查现状就写，会写出重复条目；只提炼不归类，文件会越开越多。

**它是这棵树唯一的写者** —— 写入和维护都归它。

# 写入全自动

**新增、改写、删除都不问人，直接写。**

理由：写的时候不知道以后会用到什么，在这里判断只能靠赌；而 git 让写盘可回滚，赌错的代价被压成「下次读到才发现」。判断的正确落点在读的那一刻 —— 那里有现场可核，见 `memo-load`。

**唯一的硬拦：凭据与私事。** 由 `~/memo/.git/hooks/pre-commit` 调 `scripts/guard.sh` 扫描，命中即中止提交。这条**不靠判断，靠机械检查** —— 它是「写错了只是噪音」和「写错了是留在盘上的债」的分界。

**commit 是流程的一部分，不是额外动作。** 一次阶段边界 = 一个 commit，不要每改一条就提交一次。message 一行：动了哪个文件、加了什么结论。

```bash
git -C ~/memo add -A && git -C ~/memo commit -m "<文件>: <改了什么，一句话>"
```

这份 log 不是给人看的，是给 `memo-load` 当 diff 用的 —— 下次来靠它知道树里变了什么，而我不记得。

# 建树

**两个 Skill 里只有 `memo-save` 写盘**（`memo-load` 只读）。根目录不存在时创建：

```text
~/memo/
├── .git/       ← 本地仓库，永不设远端
├── refer/      ← 原始材料快照（带日期）
└── *.md        ← 子文档（活文档，不带日期）
```

树里不放 README：**规矩跟着 Skill 走，数据只管数据。**

```bash
mkdir -p ~/memo/refer && git -C ~/memo init -q
ln -sf "<本 skill 目录>/scripts/guard.sh" ~/memo/.git/hooks/pre-commit
test -x ~/memo/.git/hooks/pre-commit || echo "✗ 钩子悬空，守卫不会生效"
```

**钩子必须指回本 skill 自己的 `scripts/guard.sh`，不能写死安装路径。**

`<本 skill 目录>` 就是 `skill_view` 返回的 `skill_dir` —— 别自己猜、别抄一条 `~/code/...` 的路径。skill 可能装在 `~/.hermes/skills/`、某个 profile 的 `skills/`、或任何自定义目录，写死一条路径，换个位置就是**悬空链接**。

而悬空链接的失败方式是**静默的**：git 发现 `pre-commit` 不可执行就当它不存在，直接放行。没有报错、没有提示 —— 你会以为有兜底，其实一路裸奔。所以最后那行 `test -x` 不是装饰，是唯一能发现这件事的动作。

同理，若有人设过 `git config core.hooksPath`，`~/memo/.git/hooks/` 就不是生效位置，建完顺手 `git -C ~/memo config --get core.hooksPath` 核一下（空 = 默认，正确）。

**永不 push 到远端。** 这不是偏好，是前提：钩子只是兜底，历史一旦推出去就撤不回来。

# 提炼什么

一条信息值得留下，当且仅当同时满足：

1. **它是结论**，不是过程；
2. **下次做同类事会用到。**

**写之前加一道自问**：**这条删掉了，下次做同一件事我会做得不一样吗？** 不会，就是噪音。

全自动写入下这道自问比以往更重要 —— 写的时候没有人类读者替你拦，唯一的闸就是这句。没有它，这棵树会稳定地往「代码搬成自然语言」的方向长。

按这三条筛，通常只留下：

- 判据（以后怎么选）；
- 结论及其边界条件（什么情况下成立）；
- 踩过的坑（为什么不能那样做）；
- 约定（此后必须遵守的）。

明确不留下：本次做了什么、调试过程、已完成事项、只对本次任务有意义的状态、**能从代码或文件里重新读出来的东西** —— 代码是它自己的最佳副本，转成自然语言只会更差、更旧、更难核。

**绝不能留下**：凭据与密钥、别人的私事 —— 任何「删掉会比留着便宜」的东西。这条由钩子兜底，但别指望它兜住全部。

# 归类

**先找已有的子文档** —— 这一步由 `memo-load` 给出（`ls` 到的文件名），不要靠自己回忆。**不要急着新建**，按主题匹配，不按本次任务匹配。

新建子文档的门槛只有一条：

> **它会被独立检索** —— 可能只想找这一件事。

不满足就并进最接近的已有文件。

命名：

- **不带日期** —— 子文档是活文档，会被改写；
- 用**一年后还在的词**，不用当前这件事的词；
- 名词短语；
- 文件名只帮扫读，**不承担检索** —— 检索靠 frontmatter。

# 关键字（frontmatter）

每个子文档开头必须有这两行：

```markdown
---
keywords: 部署, 隧道, Access, 口令, pipipi.fqmoon.cc
says: 那个网站打不开, 登不上了, 怎么又要口令
---
```

| 字段 | 放什么 | 为什么需要 |
|---|---|---|
| `keywords` | 字面词：域名、配置键、命令、错误码、主题名词 | grep 得得到，但需要有人写下来 |
| `says` | **那句话会怎么被问出口**：症状、口头说法、旧名与别名 | 检索的触发词永远来自用户那句话，grep 自己猜不到 |

**`says` 不是给人看的** —— 它的读者是检索器。存在的唯一理由是把「那一句话」映射到「这条笔记」。

**三条硬规矩**：

1. **只放词与短说法，不放句子、不放结论** —— 写成摘要就会漂；
2. **一行一个字段，约 10 个以内**，逗号分隔；值里不要出现冒号（会坏 YAML）；
3. **两种词都要有** —— 只有主题词等于只做了一半。

文件名里已经有的词不必重复。新增文件必须带这两行；出现新的常用说法，补进 `says`。

# 写成什么样

条目 = **一句结论 + 日期 + 锚**。

```markdown
## <子主题>

- 结论内容。 (2026-11-05) `packages/app/src/x.ts:12`
- 结论内容。 (2026-11-05)
```

**锚是什么**：能回到现场的东西 —— 文件路径（带行号或符号名更好）、命令、配置键、URL。它不给人看，是给下一次的我**推翻这条结论**用的。

判断标准：**这条过期的那天，我能不能只靠锚发现它过期了？** 不能，就换个锚或者别写。

没有锚的结论，写完就永久有效 —— 没人能核，冲突时也没法判。人类读者不在了，纠错只能靠「读的时候能回现场」。

- 二级标题就是子主题，也是检索单位 —— 标题要能被目标对上；
- **日期必留** —— 它是判断新鲜度的**唯一**依据。所有条目一视同仁，不预判谁会过期；
- 不写叙述，不写「本次讨论了」。

# 原始材料放 refer/

默认**只放链接**，不复制内容：

```markdown
- 结论内容。 (2026-11-05)
  - 来源：<绝对路径 或 URL>（取自 2026-11-05）
```

只有**用户明确指定要存**时，才把材料复制进 `refer/`：

- **带日期**命名 —— 与子文档相反，因为它是快照、不改写；
- 文件开头自带来源信息：从哪来、什么时候取的；
- 子文档里指向它，而不是把内容摊进子文档。

判据与 `myenv` 一致：**Skill 自己判断不构成复制授权。**

# 只留当前有效结论

被推翻的结论**直接改写成新的**，不留墓碑：

```text
不要：曾经认为 X，后来改为 Y。
要：  Y。
```

**变化由 git diff 承担，不靠正文自述。** 下一次的我读到的是唯一有效的版本；需要知道「变过什么」时去查 diff —— 那比在文件里挂一堆历史更准，也不污染检索。

# 删除

**可以自动删。** 有了历史，「删错」不再不可逆 —— 这解掉了上一版「没用了不是删除理由」的僵局（那时删真的会丢）。反过来，留着一条不会再用的结论，代价是持续稀释检索。

| 情形 | 做什么 |
|---|---|
| **不该存在**（凭据、私事、错贴、噪音） | 立刻删 |
| 被推翻，但有替代结论 | 改写 |
| **没用了**（内容仍对，但不会再用到） | 删 —— 历史兜底 |

## 动干净清单

**先分清动的是哪一层** —— 层级错了会动到不该动的：

| 动什么 | 删 |
|---|---|
| **条目**（一个 H2 / 一条） | 删条目；若它代表那个文件的主要内容，顺带检查文件名是否还成立 |
| **文件**（最后一个条目处理完后） | 删文件 + 删**没有被引用的** refer 快照 |
| **refer 快照** | 只在确认没有子文档引用时才删（一份可能被多条引用） |

# 什么时候写

**不是只在收尾。** 两个触发面：

| 触发面 | 例子 | 为什么是这里 |
|---|---|---|
| **阶段边界** | 一个判断被推翻、一个方案定下来、踩到一个会再踩的坑、交付了一样东西 | 会话可能走不到「收尾」；等到收尾，当时的判据已经凉了，只剩结果 |
| **收尾** | 任务完成、用户说告一段落 | 把还挂着的待定项清掉 |

**粒度**：一次阶段边界 = 一次写入 = 一个 commit。不要每条洞察都停一下，也**不要全攒到最后** —— 攒到最后写出来的往往是「这次做了什么」，而不是结论。

# 维护（顺手做的结构调整）

**维护归本 Skill，看到就做，不攒着、不问。**

| 看到什么 | 做什么 |
|---|---|
| 某个二级标题下超过约 10 条 | **拆成独立子文档** |
| 两个子文档其实讲同一件事 | **并为一个** —— 用更宽的那个文件名 |
| 文件名已经对不上内容 | **改名** |
| 出现新的常用说法 / 别名 | **补进该文件的 `says`** |
| `refer/` 里有没被任何条目引用的文件 | 报告，不删（可能是用户手动放的） |

结构调整和写入一样自动 —— 都由 git 兜底，且都不改结论本身。

# 不负责

- **不做「定期通读整棵树」的巡检** —— 树的健康不再靠人审：每次写前看现状、读时按锚核对、以及 git diff。代价是**过期只有被读到才修**，不会被提前发现；
- 不记录任务进度。判据：**下次做同类事会用到 → 这里；下次接着做这件事 → `progress` / 项目的 Execution Plan**；
- 不写入当前有效结论之外的历史。

# 核心原则

> **提炼出结论、并进对的文件、写前看现状、每条带锚；只留当前有效版本，自动 commit。**
