# Memo Save

把本次会话中值得长期留下的结论，写进 memo 资料树。

**它不是「存一下」。** 完整动作是四步：

```text
提炼 → 归类 → 并进子文档 → 同步入口
```

缺任何一步，资料树都会退化：只提炼不归类，文件会越开越多；只并进不同步入口，索引会漂移。

# 建树

**三个 Skill 里只有 `memo-save` 建树。**

根目录或入口 README 不存在时创建：

```text
~/memo/
├── README.md
├── refer/
└── archive/
```

入口 README 初始内容 —— **三条规矩必须写进去**，因为它们是资料层的规矩，要跟数据走，而不是跟 Skill 走：

```markdown
# Memo

长期资料树。结论按主题分文件，条目带日期。

## 规矩

1. 改动任何子文档后，同步本文件里对应那一行。
2. 只保留当前有效结论，不留「曾经认为 X」这类墓碑。
3. 新建子文档的门槛：它会被独立检索。

## 索引

| 文件 | 内容 |
|---|---|
| — | — |

## 最近变化

- —

## 说明

- `refer/` 是原始材料快照（带日期）；引用写在子文档条目里，没被任何子文档引用的文件是孤儿。
- `hits.md` 是装载痕迹，不是文档，不参与检索。
```

只创建、不覆盖。已有 README 时沿用它的现有结构。

# 提炼什么

一条信息值得留下，当且仅当同时满足：

1. **它是结论**，不是过程；
2. **下次做同类事会用到**。

按这两条筛，通常只留下：

- 判据（以后怎么选）；
- 结论及其边界条件（什么情况下成立）；
- 踩过的坑（为什么不能那样做）；
- 约定（此后必须遵守的）。

明确不留下：本次做了什么、调试过程、已完成事项、只对本次任务有意义的状态。

# 归类

**先找已有的子文档**，不要急着新建。按主题匹配，不按本次任务匹配。

新建子文档的门槛只有一条：

> **它会被独立检索** —— 有人可能只想找这一件事。

不满足就并进最接近的已有文件。

新增时的命名：

- **不带日期** —— 子文档是活文档，会被改写；
- 用**一年后还在的词**，不用当前这件事的词；
- 名词短语，用你会说出口的词。

# 写成什么样

条目 = **一句结论 + 日期**。

```markdown
## <子主题>

- 结论内容。 (2026-11-05)
- 结论内容。 (2026-11-05)
  - 只在下次会用到时，才补最多两三条细节。
```

- 二级标题就是子主题，也是检索单位 —— 标题要能被目标对上；
- 日期必留，它是判断新鲜度的唯一依据；
- 不写叙述，不写「本次讨论了」。

# 原始材料放 refer/

默认**只放链接**，不复制内容：

```markdown
- 结论内容。 (2026-11-05)
  - 来源：<绝对路径 或 URL>（取自 2026-11-05）
```

只有**用户明确指定要存**时，才把材料复制进 `refer/`：

- **带日期**命名 —— 与子文档相反，因为它是快照、不改写；
- 文件开头自带来源信息：从哪来、什么时候取的；
- 子文档里指向它，而不是把内容摊进子文档。

判据与 `myenv` 一致：**Skill 自己判断不构成复制授权。**

# 只留当前有效结论

被推翻的结论**直接改写成新的**，不留墓碑：

```text
不要：曾经认为 X，后来改为 Y。
要：  Y。
```

保留日期即可，不需要保留 X。

# 同步入口

**改动任何子文档后，必须同步入口 README 里对应那一行，并更新「最近变化」（保留最近 5 条）。**

入口那一行同时承担索引与别名（「也叫……」）—— 这是唯一的同步点，不要在每个文件里再放一份关键词。

# 什么时候写

- 任务完成、阶段交付时；
- 用户明确表示告一段落时；
- 过程中遇到值得单独记下的坑时（允许只写一行 —— 那类信息当时最鲜活）。

# 不负责

- 不做全局整理（属于 `memo-maintain`）；
- 不记录任务进度。判据是：**下次做同类事会用到 → 这里；下次接着做这件事 → `progress` / 项目的 Execution Plan**；
- 不写入当前有效结论之外的历史。

# 核心原则

> **提炼出结论、并进对的文件、同步入口那一行；只留当前有效版本。**
