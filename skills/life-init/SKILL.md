# Life Init

**仅限用户显式调用，禁止模型主动调用。** 它建目录、init 仓库、注册定时任务 —— 都是「一次装配」的动作，不该由模型在任务中途顺手触发。

一生项目（`~/life`）的**装配器**。它只声明**需要存在什么**，不绑定某个 harness 或某台机器的做法；具体命令见文末「本机实现（参考，非规范）」。

life 是什么、什么该进，由 `life` Skill 定义 —— 本 Skill 只管把这棵树建起来，不解释它的内容判据。

**它是一次性的动作，但必须可重复执行。** 换机器、配置丢了、仓库坏了、定时任务被删了 —— 重跑一次补齐。所以它做的是「**检查并补齐**」：已存在的跳过，缺什么补什么。

判定做完的标准不是命令跑完了，是**整条链路通**：`life-save` 能写到 commit，定时任务能把 commit 推上去。

# 装配什么

| 要素 | 需要存在什么 | 怎么算装好了（可验证） |
|---|---|---|
| 1. 根目录 | `$LIFE_ROOT`（默认 `~/life`），内含 `refer/`、`archive/` | 目录在，两个子目录在 |
| 2. 入口 | `<root>/README.md`，含下列 7 条规矩与索引表 | 文件在且规矩齐全 |
| 3. 仓库 | git 仓库，至少一次 commit，`.gitignore` 在 | `git -C <root> log` 非空；`git status` 干净 |
| 4. 远端 | **一个私有远端**，已设为 `origin` | `push` 能成功 |
| 5. 定时推送 | **每天一次的任务**，只 push，不 commit，不启动模型 | 任务存在且最近一次运行成功 |
| 6. 自检 | 上面五项都过 | 报告缺哪个 |

**它只管这五件：目录、入口、仓库、远端、定时任务。** 内容从哪来、要不要搬旧东西，不关它的事。

# 入口 README

**立意与规矩的落点是入口 README，不是 SKILL.md。** `life-load` 每次只读入口；写在 SKILL.md 开头的立意、只存在于 skill 里的规矩，**进不了装载路径**，等于没写。改立意 = 改 README，SKILL.md 只指路。

`LIFE_ROOT` 未设置时用 `~/life`。环境里若残留 `MEMO_ROOT`，说明是旧树的变量，**报告出来，不要静默采用**。

模板 = **骨架**：标题、`## 为什么叫 life`、`## 它是什么`、`## 它不是什么`、`## 规矩`、`## 说明` 的固定文字。

**不覆盖** `## 索引` 与 `## 最近变化` —— 那是活数据，由 `life-save` 维护；模板里只放空占位（`| — | — |` 与 `- —`）。

一致性校验（改完 README 就跑一次）：

```bash
awk '/^## 索引/{skip=1} /^## 说明/{skip=0} !skip' ~/life/README.md > /tmp/live.md
awk '/^```markdown$/{f=1;next} /^```$/{f=0} f' ~/skills/skills/life-init/SKILL.md \
  | awk '/^## 索引/{skip=1} /^## 说明/{skip=0} !skip' > /tmp/tpl.md
diff /tmp/tpl.md /tmp/live.md && echo TEMPLATE_IN_SYNC
```

```markdown
# Life

一个人的项目文档。项目是：这个人的人生。

（Agent 视角的完整定义与边界见 `skills/life`；本文件是树内的自解释副本，判据改动要两处同步。）

## 为什么叫 life

不叫 `brain`，也不叫 `memo`：那两个词只描述**功能**（一个记东西的地方），把「一辈子」压成了「一次查询」。

`life` 说的是**视角**：一个人的人生就是一个项目。所以这里记的是这个项目的过程 —— 现在在做什么、定了什么、否决了什么、还欠着什么。

## 它是什么

**一个记忆仓库**，和 memo 那套一样：按主题分子文档、入口 README 做索引、每条带日期。理念是项目文档，但**结构不学项目文档** —— 没有 `STATUS.md`，没有 `ADR/` 目录；状态、决定、否决、遗留都是条目，写进对应的主题文件里。

## 它不是什么

- 不是日记（按天排的流水）—— 历史在 `git log`；
- 不是知识库（外部世界的知识不进这里，主语必须是「我」）；
- 不是自动的 —— 没有你写下的那句话，它不会自己变好。

## 规矩

1. 它记当前状态与决定，不记流水：只留转折点，不留流水全集。
2. 主体是**你**，这是**上位**层：项目资料也在内 —— 因为它代表「我的人生里做过这个」。判据不是「跨不跨项目」，而是**「五年后的我，会不会为了理解自己而翻它」**。会 → 进这里，粒度是「我做过什么、学到什么」；不会（纯配置值、纯进度）→ 留在项目里（intent / ADR / progress / debt）。
   **主语判据：每条的主语必须是「我」。** 主语是项目/模块/系统 → 那是项目文档，不是这里；有项目字眼不算错，它只是场景。
3. 条目写**判据**不写**记录**：「遇到 X 先看 Z」省一次决策，「我把 X 改成 Y」只省一次检索。
4. 入树门槛：只有「下次遇到我会因此做错一件事」的才进。
5. **正文是当前状态，不是日记**：任何时刻读它，读到的都是「我现在相信什么」，不含时间线。时间线归 git —— `git log` 就是日记。条目上的日期是这条**最近一次确认的时间**（新鲜度），不是事件发生的时间。
   推论：同一件事只能有一条说法，出现两条就是状态不一致（bug），必须合并 —— 日记里两条并存正常，状态文件里不正常。
6. 改与删先告知（git 可回滚，所以是告知与确认，不是审批）。
7. 优化命中率不是完整度：二十条每次都被读到，胜过两百条烂在盘上。
```

# 仓库与远端：需求

- **本地先提交是廉价的，推送是异步的。** commit 归 `life-save`（写的人知道「为什么」），推送归定时任务。两者分开，所以远端挂掉不影响继续写。
- **身份必须显式传**，不要依赖全局 `~/.gitconfig` —— 定时任务的环境里它可能不存在，失败还是静默的：
  `git -C <root> -c user.name=... -c user.email=... commit ...`
- **远端必须是私有的，且推之前确认树里没有凭据值**：只记位置可以（`~/cloudflared/...`），记值不行。私有不等于安全 —— 一推上去就随历史走，删要重写历史。
- `.gitignore` 至少含编辑器垃圾（`*.swp`、`.DS_Store`）。

# 定时推送：需求

只要满足下面五条，用什么调度器都行：

| 需求 | 为什么 |
|---|---|
| **每天一次**，本地清晨 | 当天改动当天落袋，出事最多丢一天 |
| **只 push，不 commit** | commit 的时机在写作现场，机器补不了「为什么」 |
| **不启动模型** | 纯搬运，叫模型只是多一轮成本 |
| **无事可做就静默** | 没改动、没远端、没领先 —— 不该每天报平安 |
| **失败必须可见** | 静默失败最坏：你以为在备份，其实半年没推上去过 |

最后一条是关键：这条任务**唯一可能出错的方式是静默**，所以「失败通知」不是可选优化。

# 本机实现（参考，非规范）

以下是这台机器（Hermes + systemd 主机）上的做法，换个 harness 就换掉这一节，上面那些需求不变。

脚本 `~/.hermes/scripts/life_push.sh`：

```bash
#!/usr/bin/env bash
set -u
ROOT="${LIFE_ROOT:-$HOME/life}"
[ -d "$ROOT/.git" ] || exit 0
git -C "$ROOT" remote get-url origin >/dev/null 2>&1 || exit 0
out=$(git -C "$ROOT" -c user.name=life -c user.email=life@localhost \
        -c core.quotepath=false push -q origin HEAD 2>&1) || {
  echo "[life] push 失败：$out"; exit 1; }
```

建私有远端（**对外可见，动手前先确认仓库名与可见性**）：

```bash
gh repo create <owner>/life --private --source="$ROOT" --remote=origin --push
```

注册任务（Hermes）：

```bash
hermes cron create "0 6 * * *" --name "life 推送" --no-agent \
  --script life_push.sh --deliver local --failure-deliver origin
```

- `--no-agent`：满足「不启动模型」；
- `--deliver local`：正常不打扰；
- `--failure-deliver origin`：满足「失败必须可见」；
- 定时任务挂在**注册它的那个 profile** 下；换 profile 时它不会跟着走，重跑本 skill 补齐。

# 不负责

- 不写结论（那是 `life-save`）；
- 不改写结论、不删条目；
- 不迁移旧内容（一次性的人工动作，不固化进 skill）；
- 不擅自创建远端仓库（对外可见，动前确认）；
- 不删旧树与旧 skill。

# 核心原则

> **声明需要什么，用当前环境补齐；重跑任意次结果相同。**
