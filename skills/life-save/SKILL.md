# Life Save

把本次会话中值得长期留下的结论，写进第二大脑（`$LIFE_ROOT`，默认 `~/life`）。

**它不是「存一下」。** 完整动作是六步：

```text
提炼 → 查现状（调 life-load）→ 归类 → 并进子文档 → 同步入口 → 提交
```

**第二步不能省，也不能靠记忆。** 写之前先看树里现在是什么状态：目标文件已有什么、该并入哪一节、有没有要改写的旧结论。

**最后一步不能省。** 正文只留当前有效版本、不留墓碑 —— 所以「我改过主意」这件事**只存在于 git 历史里**。不提交，等于这次改动没有理由。

**它是这棵树唯一的写者** —— 写入和维护都归它。

# 这棵树是什么

你的**判据集**，主体是**你**，不跟项目走。所以：

- 换个项目还成立 → 进这里；不成立 → 留在项目里（`intent` / `ADR` / `progress` / `debt`）；
- 它**允许**写「我判断错了」「我当时没看懂就点头了」—— 没有受众，没有社交成本。反过来：**一条只有成功经验、没有判断失误的记录，已经退化成项目文档了。**

# 交互

**新增不问；改和删先列清单问一次；结束一定汇报。**

| 动作 | 问不问 | 为什么 |
|---|---|---|
| **新增** | 不问 | 非破坏性 |
| **改**（改写被推翻的结论） | **列清单，一次问** | 旧的那句会消失（虽可回滚） |
| **删 / 归档** | **列清单，一次问** | 同上 |

有了 git，这两道闸门**从「审批」降成「告知 + 确认」**：误改可以 `checkout` 回来。保留它的理由是「我要知道这次动了什么」，不是「怕丢」。

**结束必须汇报变化了哪些** —— 无论有没有改删。这是用户唯一能看到这次写了什么的地方。

| 这次干了什么 | 汇报什么 |
|---|---|
| 只新增 | 新增了哪几条 → 落到哪个文件 |
| 有改 / 有删 | 先问（清单）→ 做完 → 汇报最终变化 |
| 什么都没写 | 直说「这次没有值得留下的」 |

# 提炼什么

一条信息值得留下，当且仅当：

1. **它是结论**，不是过程；
2. **下次遇到我会因此做错一件事**。

第二条比「下次会用到」硬得多 —— 它砍掉八成候选。按这两条筛，只留下：

- 判据（以后怎么选、先看什么）；
- 结论及其边界（什么情况下成立、什么情况下失效）；
- 踩过的坑（为什么不能那样做）；
- 约定（此后必须遵守的）。

明确不留：本次做了什么、调试过程、已完成事项、只对本次任务有意义的状态。

**绝不能留**：凭据与密钥、别人的私事 —— 任何「删掉比留着便宜」的东西。这一条比上面两条更硬：判断错了只是噪音，这里错了是**留在盘上的债**（而且一旦推到远端就收不回来）。

# 归类

**先找已有子文档** —— 由 `life-load` 给出，不要靠自己回忆。**不要急着新建**：按主题匹配，不按本次任务匹配。

新建子文档只有一个门槛：

> **它会被独立检索** —— 有人可能只想找这一件事。

新增时的命名：

- **不带日期** —— 子文档是活文档；
- 用**一年后还在的词**，不用当前这件事的词；
- 名词短语，用你会说出口的词。

# 写成什么样

条目 = **一句结论 + 日期**。

```markdown
## <子主题>

- 结论内容。 (2026-11-07)
- 结论内容。 (2026-11-07)
  - 只在下次会用到时，才补最多两三条细节。
```

- 二级标题就是子主题，也是检索单位；
- **日期必留** —— 它是判断新鲜度的唯一依据；不预判谁会过期；
- 写**判据**不写**记录**：「遇到 X 先看 Z」省一次决策；「我把 X 改成 Y」只省一次检索。

```text
不要：曾经认为 X，后来改为 Y。
要：  Y。 (2026-11-07)
```

# 原始材料放 refer/

默认**只放链接**，不复制内容：

```markdown
- 结论内容。 (2026-11-07)
  - 来源：<绝对路径 或 URL>（取自 2026-11-07）
```

只有**用户明确指定要存**时，才复制进 `refer/`（带日期命名、开头写来源）。**Skill 自己判断不构成复制授权。**

# 删除与归档

| 情形 | 做法 |
|---|---|
| **不该存在**（凭据、私事、错贴、噪音） | **直接删** —— 它是事实，删掉比留着便宜 |
| **没用了**（判断：大概不再需要） | **归档** —— 判断不该有删除权，软删就够 |
| 被推翻，但有替代结论 | **改写** |

**归档 = 移出检索范围但保留**：装进 `archive/`，索引那行删掉，正文里删掉。`archive/` 里的内容不参与装载，也不列在索引里。

动的时候先分清层：动**条目**（连同日期追加到 `archive/<原文件名>`）还是动**文件**（移入 `archive/` + 删索引行 + 删 `最近变化` 那行 + `hits.md` 行）。`refer/` 快照只在确认没被任何条目引用时才删。

# 同步入口

**改动任何子文档后，必须同步入口 README 里对应那一行，并更新「最近变化」（保留最近 5 条）。**

「最近变化」只写**文件名 + 日期**（`第二大脑.md  2026-11-07`），不写内容 —— 它只回答「哪几个文件最近动过」。因为不记内容，删除时也照写。

入口那一行同时承担索引与别名（「也叫……」）—— 这是唯一的同步点。

# 提交

**第五步做完立刻提交，不要拖到下次。**

```bash
git -C "$ROOT" add -A
git -C "$ROOT" diff --cached --quiet && echo "无改动" && exit 0
git -C "$ROOT" -c user.name=life -c user.email=life@localhost commit -q -m "<消息>"
```

**消息必须带理由** —— 它是这次判断唯一的存档，正文里不留墓碑：

| 动作 | 消息形状 |
|---|---|
| 新增 | `增：<子主题> — <一句话：它解决什么判断>` |
| 改写 | `改：<子主题> — <旧判断> → <新判断，以及为什么>` |
| 归档 | `归：<文件> — <为什么不再指望>` |
| 删除 | `删：<条目> — <为什么它不该存在>` |

一次收尾改了多处 → **一次 commit**，用 `-m` 多段（标题 + 正文）。

**不许写**：`update`、`整理`、日期本身，或任何不带理由的词。这些消息等于没有理由，比不做版本管理更糟 —— 它伪装成了历史。

# 维护（顺手做的结构调整）

**看到就做，不攒着**（都属于改结构，仍要告知）：

| 看到什么 | 做什么 |
|---|---|
| 某二级标题下超过约 10 条 | 拆成独立子文档，旧标题作为别名留在入口 |
| 两个子文档讲同一件事 | 并为一个，被并掉的名字作为别名留在入口 |
| `refer/` 有没被引用的文件 | 报告，**不删** |
| `hits.md` 有指向已删文件的行 | 直接删掉那行 |

# 不负责

- 不做「定期通读整棵树」的巡检 —— 健康靠每次收尾做对 + 结束汇报；代价是漂移没有兜底；
- 不记录任务进度（那属于 `progress` / 项目的 Execution Plan）；
- 不注册 cron、不配远端（那是 `life-init`）；
- 不写 git 消息以外的事件史。

# 核心原则

> **提炼出判据、并进对的文件、同步入口那一行、提交时写清理由。**
