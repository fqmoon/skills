# Life Save

把本次会话中值得长期留下的结论，写进第二大脑（`$LIFE_ROOT`，默认 `~/life`）。

**它不是「存一下」。** 完整动作是六步：

```text
提炼 → 查现状（调 life-load）→ 归类 → 并进子文档 → 同步入口 → 写待提交消息
```

**第二步不能省，也不能靠记忆。** 写之前先看树里现在是什么状态：目标文件已有什么、该并入哪一节、有没有要改写的旧结论。

**它不提交，但必须给提交准备好消息。** 提交由定时兜底（`life-init` 装的 cron，每天一次）执行；它读的是一份你写好的待提交消息 —— 没有它，历史就只剩一句「改动 N 个文件」，`git log` 读不出任何东西。

正文只留当前有效版本、不留墓碑，所以「我改过主意」这件事只存在于 git 历史里。**让那份历史可读，就等于让演变可知。**

**它是这棵树唯一的写者** —— 写入和维护都归它。

# 这棵树是什么

你的**判据集**，主体是**你**，而且是**上位**层 —— 项目资料也在内：一个项目就是你人生里的一段。所以：

- 判据不是「跨不跨项目」，是**「五年后的我，会不会为了理解自己而翻它」**。会 → 进这里，粒度是「我做过什么、学到什么」；纯配置值与纯进度 → 留在项目里（`intent` / `ADR` / `progress` / `debt`）；
- **主语必须是「我」** —— 这条是最容易守也最容易破的。主语是项目/模块/系统，那是项目文档；出现项目名字不违规，它只是场景；
- 它记**人的项目**，不记项目本身：为什么接、想做成什么、卡在哪、改了哪个想法、付出了什么代价；
- 两边**不镜像**：项目里存值，这里存这一段的意义、判据与坑；
- 它**允许**写「我判断错了」「我当时没看懂就点头了」—— 没有受众，没有社交成本。反过来：**一条只有成功经验、没有判断失误的记录，已经退化成项目文档了。**

# 交互

**新增不问；改和删先列清单问一次；结束一定汇报。**

| 动作 | 问不问 | 为什么 |
|---|---|---|
| **新增** | 不问 | 非破坏性 |
| **改**（改写被推翻的结论） | **列清单，一次问** | 旧的那句会消失（虽可回滚） |
| **删 / 归档** | **列清单，一次问** | 同上 |

有了 git，这两道闸门**从「审批」降成「告知 + 确认」**：误改可以 `checkout` 回来（窗口是到下次定时提交前，最多一天）。保留它的理由是「我要知道这次动了什么」，不是「怕丢」。

**结束必须汇报变化了哪些** —— 无论有没有改删。这是用户唯一能看到这次写了什么的地方。

| 这次干了什么 | 汇报什么 |
|---|---|
| 只新增 | 新增了哪几条 → 落到哪个文件 |
| 有改 / 有删 | 先问（清单）→ 做完 → 汇报最终变化 |
| 什么都没写 | 直说「这次没有值得留下的」 |

# 提炼什么

一条信息值得留下，当且仅当：

1. **它是结论**，不是过程；
2. **下次遇到我会因此做错一件事**。

第二条比「下次会用到」硬得多 —— 它砍掉八成候选。按这两条筛，只留下：

- 判据（以后怎么选、先看什么）；
- 结论及其边界（什么情况下成立、什么情况下失效）；
- 踩过的坑（为什么不能那样做）；
- 约定（此后必须遵守的）。

明确不留：本次做了什么、调试过程、已完成事项、只对本次任务有意义的状态。

**绝不能留**：凭据与密钥、别人的私事 —— 任何「删掉比留着便宜」的东西。这一条比上面两条更硬：判断错了只是噪音，这里错了是**留在盘上的债**（而且一旦推到远端就收不回来）。

# 归类

**先找已有子文档** —— 由 `life-load` 给出，不要靠自己回忆。**不要急着新建**：按主题匹配，不按本次任务匹配。

新建子文档只有一个门槛：

> **它会被独立检索** —— 有人可能只想找这一件事。

新增时的命名：

- **不带日期** —— 子文档是活文档；
- 用**一年后还在的词**，不用当前这件事的词；
- 名词短语，用你会说出口的词。

# 写成什么样

条目 = **一句结论 + 日期**。

```markdown
## <子主题>

- 结论内容。 (2026-11-07)
- 结论内容。 (2026-11-07)
  - 只在下次会用到时，才补最多两三条细节。
```

- 二级标题就是子主题，也是检索单位；
- **日期必留** —— 它是判断新鲜度的唯一依据（= 这条最近一次确认的时间），不是事件时间；
- **正文是状态不是日记**：写「现在是什么」，不写「几号改成了什么」。时间线在 `git log` 里，别在正文里再抄一份；
- 写**判据**不写**记录**：「遇到 X 先看 Z」省一次决策；「我把 X 改成 Y」只省一次检索。

```text
不要：曾经认为 X，后来改为 Y。
要：  Y。 (2026-11-07)
```

# 原始材料放 refer/

默认**只放链接**，不复制内容：

```markdown
- 结论内容。 (2026-11-07)
  - 来源：<绝对路径 或 URL>（取自 2026-11-07）
```

只有**用户明确指定要存**时，才复制进 `refer/`（带日期命名、开头写来源）。**Skill 自己判断不构成复制授权。**

# 删除与归档

| 情形 | 做法 |
|---|---|
| **不该存在**（凭据、私事、错贴、噪音） | **直接删** —— 它是事实，删掉比留着便宜 |
| **没用了**（判断：大概不再需要） | **归档** —— 判断不该有删除权，软删就够 |
| 被推翻，但有替代结论 | **改写** |

**归档 = 移出检索范围但保留**：装进 `archive/`，索引那行删掉，正文里删掉。`archive/` 里的内容不参与装载，也不列在索引里。

动的时候先分清层：动**条目**（连同日期追加到 `archive/<原文件名>`）还是动**文件**（移入 `archive/` + 删索引行 + 删 `最近变化` 那行 + `hits.md` 行）。`refer/` 快照只在确认没被任何条目引用时才删。

# 同步入口

**改动任何子文档后，必须同步入口 README 里对应那一行，并更新「最近变化」（保留最近 5 条）。**

「最近变化」只写**文件名 + 日期**（`第二大脑.md  2026-11-07`），不写内容 —— 它只回答「哪几个文件最近动过」。因为不记内容，删除时也照写。

入口那一行同时承担索引与别名（「也叫……」）—— 这是唯一的同步点。

# 写待提交消息

**收尾的最后一个动作**：把这次改动的说明写进 `<root>/.commit-msg`（不进版本库），然后结束。cron 会读它、提交、删掉它。

格式：**第一行一句话，其后分条。**

```text
`life-load` 的检查项加了「状态打架」
- 同一件事两处说法不再放过
- 「不是日记」拆成独立检查项
- 文件：README.md      ← 末行由脚本追加，不用写
```

- 第一行是一句**完整的话**，说清这次改了什么 —— 它就是 `git log --oneline` 的全部内容，含糊等于没写；
- **不加前缀**（不要 `增：`/`改：` 这类）—— 动作类型不值钱，不值得占掉第一行的位置，用词本身写清楚即可；
- 分条：**一条一件事**，别把文件清单当条目写；
- 一次收尾只写一份，覆盖旧的；没有改动就别写，写了也会被清掉。

**不许写**：`update`、`整理`、日期本身，或任何不带理由的词。

**示例里出现的每个记号，必须在同一节定义。** 用了一个不解释的记号，执行的人只能猜。格式里的约定，要么紧跟定义，要么就别用。

# 维护（顺手做的结构调整）

**看到就做，不攒着**（都属于改结构，仍要告知）：

| 看到什么 | 做什么 |
|---|---|
| 某二级标题下超过约 10 条 | 拆成独立子文档，旧标题作为别名留在入口 |
| 两个子文档讲同一件事 | 并为一个，被并掉的名字作为别名留在入口 |
| `refer/` 有没被引用的文件 | 报告，**不删** |
| `hits.md` 有指向已删文件的行 | 直接删掉那行 |

# 不负责

- 不做「定期通读整棵树」的巡检 —— 健康靠每次收尾做对 + 结束汇报；代价是漂移没有兜底；
- 不记录任务进度（那属于 `progress` / 项目的 Execution Plan）；
- **不提交、不写 commit 消息** —— 提交归定时兜底（`life-init`）；
- 不注册 cron、不配远端（那是 `life-init`）；
- 不写 git 消息以外的事件史。

# 核心原则

> **提炼出判据、并进对的文件、同步入口那一行、写好一句话 —— 提交交给定时器。**
