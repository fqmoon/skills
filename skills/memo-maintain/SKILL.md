# Memo Maintain

对 memo 资料树做**全局**整理。

它与 `memo-save` 的分工是频率与范围：

```text
memo-save      每次收尾，只读目标文件     —— 必须便宜
memo-maintain  低频，通读整棵树           —— 必然贵
```

因此本 Skill 不承担日常写入。它存在的意义是让 `memo-save` 依赖的那两条规矩 —— 「改子文档要同步入口」和「只留当前有效结论」—— **从自觉变成可执行**。

# 动作

| 动作 | 判据 | 可逆 |
|---|---|---|
| **入口对账** | 逐个子文档，检查入口那一行是否还对（摘要过期 / 文件不存在 / 新增未登记） | 是 |
| **补别名** | 同一件事的不同叫法 → 补进入口那一行 | 是 |
| **清墓碑** | 发现「曾经认为 X」「已废弃」这类被推翻的记录 → 改写成当前结论 | 是 |
| **裁剪最近变化** | 入口「最近变化」只保留最近 5 条 | 是 |
| **清理痕迹孤儿行** | `hits.md` 里指向已不存在文件的行 → 删除 | 是 |
| **归档** | 长期不增长**且** `hits.md` 中近期无命中 → 移入 `archive/`，入口删行 | 否 |
| **提升** | 某个二级标题下超过约 10 条 → 拆成独立子文档，入口加行，**旧标题作为别名留在入口** | 否 |
| **合并** | 两个子文档其实讲同一件事 → 并为一个，**被并掉的名字作为别名留在入口** | 否 |

# 「长期不增长」怎么判

**用内容里最新的那个日期，不用文件系统时间。**

维护动作本身就会更新 mtime，用它判会把「刚被整理过」误读成「刚有新结论」。

内容里最新的日期才是「最后一次有新结论」的时间。

# 装载痕迹

`hits.md` 是文件级汇总，一行一个文件：

```text
agent-tooling.md     last 2026-11-05    hits 12
```

维护时：

- 删掉指向已不存在文件的行；
- 归档判据读的是这里的 `last`；
- **文件不存在（从未装载过）时，归档只按「长期不增长」判断**，并在报告中说明这一限制 —— 不要因为缺证据就当成「没人读」而误归档。

# 改还是报告

- **可逆的直接改**（对账、别名、清墓碑、裁剪、清理孤儿行），并写入变更清单；
- **不可逆的先报告**（归档、提升、合并）—— 这三类判错后恢复成本高。

变更清单写给记录，不要求用户逐条阅读。需要用户决策的不可逆动作，单独列出。

# 报告孤儿

以下两类**不直接删**，只在报告里列出：

- `refer/` 里没有被任何子文档引用的文件（可能是用户手动放的）；
- 入口里登记了、但文件不存在且找不到别名的条目。

# 完成条件

- 入口里每一行都对应一个存在的文件；
- 每个存在的文件都在入口里有一行（`archive/`、`refer/`、`hits.md` 除外）；
- 没有被推翻的结论仍以「曾经」「已废弃」的形式留在正文里；
- `hits.md` 里没有指向已删文件的行；「最近变化」不超过 5 条；
- 超过阈值的子主题已被提升，或已在报告中列出。

# 不负责

- 不新增结论（属于 `memo-save`）；
- 不修改结论的语义，只整理结构与索引；
- 不删除 `refer/` 里的任何文件；
- 不因为「看起来重复」就删除内容 —— 合并必须保留全部有效信息。

# 核心原则

> **整理结构，不重写内容；可逆的直接改，不可逆的先报告。**
