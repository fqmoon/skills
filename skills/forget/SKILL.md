用途
- 为结束当前会话并开启新会话准备交接信息。
- 收集下一会话继续工作可能需要的信息。
- 通过迭代式人工确认删除不需要继续传递的信息。
- 让最终未进入交接文档的信息随旧会话一起被遗忘。

输入
- 当前会话的完整历史记录。
- 当前项目的代码和文档状态。
- 现有的 FORGET 文档，如果存在。

输出
- 一个可独立理解的当前工作状态。
- 输出写入 FORGET.md。
- FORGET.md 通过追加和人工批准的删除逐步形成。

核心原则
- 只描述下一会话需要知道的当前世界。
- 不总结完整会话历史。
- 不保存仅用于解释当前结论的讨论过程。
- 不通过否定、废弃说明或历史回顾重新引入应该遗忘的对象。
- 收集和遗忘是两个独立阶段：
  - 收集阶段只允许追加。
  - 遗忘阶段只允许删除用户明确批准的内容。
- Agent 不得自行修改、合并、重写或删除已有内容。

核心流程，如果任意一步不满足，则**中止运行**
1. 查找 FORGET 文档，检查数量 <= 1；否则中止运行。
2. 遍历完整会话，识别下一会话继续工作可能需要的信息。
3. 结合当前项目状态，确认候选信息具有继续传递的价值。
4. 执行收集阶段：
   - FORGET.md 不存在时创建文档。
   - 将新增候选信息追加到对应分类。
   - 不修改任何已有正文。
5. 完成追加后，进入交互式压缩阶段。
6. 每轮：
   1. 重新读取当前 FORGET.md。
   2. 选择最多 3 个最适合删除的条目或连续段落。
   3. 列出候选原文及一句删除理由。
   4. 等待用户明确选择。
   5. 只删除用户明确批准的候选。
   6. 未获批准的内容保持原样。
   7. 删除完成后重新读取 FORGET.md，开始下一轮。
7. 用户要求停止时立即结束。
8. 如果不存在合理的删除候选，则结束。
9. 不自动结束当前会话，不自动创建新会话，不自动执行 Git 操作。

FORGET 文档
- 名字为 FORGET.md。
- 文档位置，按下列优先级查找：
  1. 项目根目录下的 docs 或 doc 目录。
  2. 项目根目录。
- 文档创建位置，同上优先级。
- 文档表示允许传递到下一会话的信息集合。
- 已有正文默认保持原样。
- 已有内容只能通过交互式删除流程删除。
- 删除后的内容不留下墓碑、删除记录或历史说明。

收集阶段
- 逐段检查完整会话历史。
- 仅考虑与当前项目或任务直接相关，且下一会话可能仍需要的信息。
- 初次收集采用保守策略：无法确定是否可以遗忘的信息先保留。
- 新信息以独立条目追加。
- 追加到现有分类时，只在该分类末尾增加新条目。
- 不为了整理格式而移动已有条目。

追加规则
- 已有 FORGET.md 的正文保持原样。
- 不修改已有条目的任何文字。
- 不重写已有条目。
- 不合并已有条目。
- 不移动已有条目。
- 不删除已有条目。
- 新识别出的信息单独追加。
- 只有与已有条目文字完全相同的新条目可以跳过。
- 语义近似的条目仍然追加。
- 部分重叠的条目仍然追加。
- 一个条目包含另一个条目的信息时仍然追加。
- 可以合并的条目仍然分别保留。
- 所有冗余和近似内容统一留到交互式压缩阶段处理。

搜索类型
- Current State
  - 当前已经实现或完成到什么程度。
  - 当前工作树、模块或功能的重要状态。
  - 下一步工作直接依赖的现状。
- Decisions
  - 当前仍然有效的设计、实现、命名或方案决定。
  - 只记录当前采用的状态。
- Constraints
  - 后续工作必须遵守的限制、兼容要求或边界。
  - 项目级工作规则。
- Open Issues
  - 当前仍未解决并且下一会话可能继续处理的问题。
- Questions
  - 尚未回答并且会影响后续工作的关键问题。
- Next Actions
  - 已明确提出并且尚未完成的下一步工作。
- Required Facts
  - 下一会话理解上述事项所依赖的事实。
- 不要求所有类型都出现。

交互式压缩
- 每轮最多提出 3 个删除候选。
- 候选必须是可以独立删除的条目或连续段落。
- 不一次性规划后续所有删除轮次。
- 每轮实际删除后，必须重新读取并重新评估剩余文档。
- 条目数量减少是结果，不是目标。
- 不为了减少条目数量而把多个独立信息合并成一个条目。
- 压缩阶段只执行删除，不执行合并或改写。

删除候选优先级
优先考虑：
1. 与其他条目表达相同状态的信息。
2. 被其他条目完整覆盖的信息。
3. 可以直接从当前代码或正式项目文档获得、且无需交接的信息。
4. 解释性背景或推导过程。
5. 与当前 Open Issues、Questions、Next Actions 无直接关系的信息。
6. 已经不影响后续工作的状态信息。

以下内容应更加保守：
- 独立的 Constraints。
- 尚未解决的 Open Issues。
- 尚未回答的 Questions。
- 尚未完成的 Next Actions。
- 其他条目依赖的 Required Facts。

用户确认
- 每轮必须列出带编号的删除候选。
- 每个候选包含：
  - 原始内容。
  - 一句删除理由。
- 用户可以：
  - 指定一个或多个编号：删除这些候选。
  - `all`：删除本轮全部候选。
  - `keep`：本轮候选全部保留，继续寻找其他候选。
  - `stop`：立即结束压缩。
- 未得到用户明确批准的内容不得删除。
- 用户选择保留的候选，在本次运行中不再次提出，除非用户主动要求重新考虑。

禁止重新引入
- 最终 FORGET.md 不写“不要使用 X”。
- 不写“X 已废弃”。
- 不写“之前考虑过 X”。
- 不写“从 X 改成 Y”。
- 不写“过去使用 X，现在使用 Y”。
- 如果 X 不应该进入下一会话，只描述当前有效状态 Y。
- 删除内容后，不在文档中记录被删除内容或删除原因。

必要历史的例外
- 如果不知道某个历史事实会直接导致下一会话重复犯错、破坏兼容性或违反外部约束，应优先保留该历史产生的当前约束，而不是历史事件本身。

例如：

错误：
- 之前方案 A 导致循环依赖，所以不要再使用 A。

正确：
- 模块 X 不得依赖模块 Y。

条目粒度
- 每个新增条目只包含一个核心信息。
- 将包含多个独立事实的新增内容拆成多个条目。
- 不把整个会话压缩成一个总条目。
- 不使用“本次讨论了……”之类的会话摘要表达。
- 条目脱离原会话后仍应能够理解。

表达规则
- 新增条目使用事实性短句。
- 优先描述当前状态，而不是变化过程。
- 保留必要的具体名称、路径、命令、参数、错误信息和版本。
- 区分已经确认的事实与仍待验证的问题。
- 不补充会话中没有出现的事实。
- 不根据常识擅自修正用户或模型已经形成的结论。
- 表达规则只适用于新增内容，不用于改写已有内容。

默认格式
- 优先沿用现有 FORGET.md 的分类和格式。
- 文档不存在时使用以下结构：

```markdown
# Forget

## Current State

- ...

## Decisions

- ...

## Constraints

- ...

## Open Issues

- ...

## Questions

- ...

## Next Actions

- ...

## Required Facts

- ...
```

- 没有内容的章节可以省略。
- 不创建 History、Rejected、Deprecated、Previous 等历史章节。

完成条件
- 已遍历当前会话，而不是只依据最后几轮消息。
- 当前会话中需要继续传递的新信息已经追加。
- 追加阶段没有修改、合并、移动或删除已有正文。
- 所有实际删除均得到用户明确批准。
- 每轮删除后都重新读取并评估剩余文档。
- 用户要求停止时已经立即停止。
- 没有通过否定句、删除记录或历史说明重新引入已删除对象。
- 未执行会话切换、Git 提交或其他超出交接文档范围的操作。
