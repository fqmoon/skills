用途
- 为结束当前会话并开启新会话准备交接信息。
- 从当前会话中提取下一会话继续工作所必需的最小状态。
- 让未进入交接文档的信息随旧会话一起被遗忘。
- 交接文档用于人工审查，不代表自动完成遗忘。

输入
- 当前会话的完整历史记录。
- 当前项目的代码和文档状态。
- 现有的 FORGET 文档，如果存在。

输出
- 一个可独立理解的当前工作状态。
- 输出写入 FORGET.md。
- FORGET.md 是可修改的状态快照，不是追加式历史记录。

核心原则
- 只描述下一会话需要知道的当前世界。
- 不总结完整会话历史。
- 不保存仅用于解释当前结论的讨论过程。
- 不保存已经失去后续价值的信息。
- 不通过否定、废弃说明或历史回顾重新引入应该遗忘的对象。
- 如果某个对象不应该出现在下一会话中，则不要在交接文档中提到它。

核心流程，如果任意一步不满足，则**中止运行**
1. 查找 FORGET 文档，检查数量 <= 1；否则中止运行。
2. 遍历完整会话，识别下一会话继续工作所必需的信息。
3. 结合当前项目状态，确认这些信息仍然有效。
4. 删除已有 FORGET.md 中已经过期、不再需要或不应继续传递的信息。
5. 合并重复信息，将状态整理为最小可用集合。
6. 检查文档中是否出现不应继续传递的历史对象、失败路径或无关信息。
7. 使用新的完整内容覆盖 FORGET.md。
8. 输出变更结果，等待人工审查。
9. 不自动结束当前会话，不自动创建新会话，不自动执行 Git 操作。

FORGET 文档
- 名字为 FORGET.md。
- 文档位置，按下列优先级查找：
  1. 项目根目录下的 docs 或 doc 目录。
  2. 项目根目录。
- 文档创建位置，同上优先级。
- 文档表示当前状态，可以增加、修改和删除已有内容。
- 文档不是历史记录，不要求保留旧状态。

搜索方法
- 逐段检查会话历史。
- 仅考虑与当前项目或任务直接相关，且下一会话继续工作时仍然需要的信息。
- 对每个候选信息执行最小化判断：如果删除该信息，新会话是否仍能正确继续工作；如果能，则不保留。
- 搜索以下类型：
  - Current State
    - 当前已经实现或完成到什么程度。
    - 当前工作树、模块或功能的重要状态。
    - 下一步工作直接依赖的现状。
  - Decisions
    - 当前仍然有效的设计、实现、命名或方案决定。
    - 只记录最终采用的当前状态。
    - 除非下一会话必须知道原因，否则不记录决策过程。
  - Constraints
    - 后续工作必须遵守的限制、兼容要求或边界。
    - 项目级工作规则。
    - 当前实现不可违反的条件。
  - Open Issues
    - 当前仍未解决并且下一会话可能继续处理的问题。
    - 已确认存在但尚未修复的缺陷或异常。
  - Questions
    - 尚未回答，并且会影响后续工作的关键问题。
  - Next Actions
    - 已明确提出并且尚未完成的下一步工作。
  - Required Facts
    - 下一会话理解上述事项所直接依赖的事实。
    - 只有缺少该事实会导致误解或重复调查时才保留。
- 不要求所有类型都出现。

遗忘规则
- 已完成且不再影响后续工作的事项不保留。
- 已解决问题的排查过程不保留。
- 临时猜测、探索过程和搜索路径不保留。
- 与后续任务无关的代码阅读结果不保留。
- 已失效的状态不保留。
- 已经被当前状态完全取代的信息不保留。
- Agent 为解释结论产生的大量推理性文字不保留。
- 单纯为了说明曾经发生过什么的历史信息不保留。

禁止重新引入
- 不写“不要使用 X”。
- 不写“X 已废弃”。
- 不写“之前考虑过 X”。
- 不写“从 X 改成 Y”。
- 不写“过去使用 X，现在使用 Y”。
- 如果 X 不应该进入下一会话，只描述当前有效状态 Y。

例如：

错误：
- 不要再使用旧的默认 WASM 路径。
- 之前考虑过自动加载 WASM，但已经否决。
- SDK 原来叫 X，现在改成 Y。

正确：
- WASM URL 由上层应用显式提供。
- SDK 只负责加载调用方提供的 WASM URL。
- SDK 包名为 Y。

必要历史的例外
- 如果不知道某个历史事实会直接导致下一会话重复犯错、破坏兼容性或违反外部约束，可以保留其产生的当前约束。
- 优先记录约束本身，而不是历史事件。

例如：

错误：
- 之前方案 A 导致循环依赖，所以不要再使用 A。

正确：
- 模块 X 不得依赖模块 Y。

条目粒度
- 每个条目只包含一个核心信息。
- 将包含多个独立事实的句子拆成多个条目。
- 不把整个会话压缩成一个总条目。
- 不使用“本次讨论了……”之类的会话摘要表达。
- 条目脱离原会话后仍应能够理解。

表达规则
- 使用事实性短句。
- 优先描述当前状态，而不是变化过程。
- 保留必要的具体名称、路径、命令、参数、错误信息和版本。
- 区分已经确认的事实与仍待验证的问题。
- 不补充会话中没有出现的事实。
- 不根据常识擅自修正用户或模型已经形成的结论。
- 合并真正重复的信息，但不合并仅仅相关的不同事项。

覆盖格式
- 优先沿用现有 FORGET.md 的分类和格式。
- 文档不存在对应格式时，使用以下结构：
```markdown
# Forget

## Current State

- ...

## Decisions

- ...

## Constraints

- ...

## Open Issues

- ...

## Questions

- ...

## Next Actions

- ...

## Required Facts

- ...
```
- 没有内容的章节可以省略。
- 不创建 History、Rejected、Deprecated、Previous 等历史章节。

人工审查
- FORGET.md 生成后必须由用户人工审查。
- 人工审查重点：
  - 是否遗漏下一会话必须知道的信息。
  - 是否包含本应被遗忘的信息。
  - 是否通过否定表达重新引入了应遗忘对象。
  - 是否存在可以进一步删除的非必要信息。
- Skill 不替代人工做最终遗忘决定。

完成条件
- 已遍历当前会话，而不是只依据最后几轮消息。
- 文档只包含下一会话继续工作所需的信息。
- 所有明显过期信息已从已有 FORGET.md 中删除。
- 没有把失败方案、废弃对象或无关历史通过否定句重新引入。
- 每条信息脱离旧会话后仍可以独立理解。
- 文档已经最小化。
- FORGET.md 已更新为完整的当前状态快照。
- 未执行会话切换、Git 提交或其他超出交接文档生成范围的操作。
