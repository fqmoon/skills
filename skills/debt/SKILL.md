# Debt

Debt 描述当前任务中**已经知道存在，但不一定需要现在解决的问题**。

它回答的是：

> 这个问题现在必须处理吗？

而不是：

> 这个问题存在吗？

也不是：

> 这个问题最终应不应该解决？

发现问题，并不意味着当前任务必须立即拥有它。

# Debt 的核心语义

如果一个已知问题：

- 不阻塞主要目标继续推进；
- 不会让后续实现建立在明显错误的方向、接口或不变量上；
- 不属于当前必须立即避免的高风险、不可逆问题；

那么它可以被有意识地延迟。

这种延迟不是忽略问题，而是明确：

> **现在不是处理它的正确时机。**

# 允许不安全的中间状态

实现过程中允许存在：

- 暂时失败的测试；
- 尚未补齐的边界处理；
- 临时不完整的兼容性；
- 已知但未处理的异常路径；
- 还没有 Hardening 的实现；
- 尚未清理的局部技术债。

中间状态不需要在每一步都恢复为完整、安全、可发布状态。

只要这些问题不阻塞主要目标继续推进，就可以暂时保留。

# 什么不能作为 Debt 延迟

以下问题通常应该现在处理：

## 阻塞推进

如果不处理，主要目标无法继续实现。

## 扭曲后续方向

如果继续推进，会让大量后续实现建立在错误的：

- 架构方向；
- 接口语义；
- 数据模型；
- 不变量；
- 基础假设；

之上。

## 高风险或不可逆

如果继续操作可能造成明显不可接受的：

- 数据破坏；
- 不可恢复迁移；
- 安全边界突破；
- 生产环境破坏；
- 其他高代价不可逆结果；

则不应简单作为 Debt 推迟。

这些情况不是因为“问题严重”就必须立即处理，而是因为延迟本身会改变后续成本或风险。

# Debt 不是 TODO

Debt 不意味着所有发现的问题都应该记录。

一些问题可能：

- 不值得处理；
- 未来自然消失；
- 只是局部实现噪声；
- 仅仅是“可以更优雅”；
- 没有足够价值值得后续跟踪。

这些问题可以直接放弃。

不要为了证明问题没有被忽略，而制造一个无限增长的债务清单。

# Debt 与 Hardening

Debt 是认知判断。

Hardening 是后续可能承载这些问题的地方。

```text
发现问题
   ↓
现在必须处理？
   ├─ 是 → 当前处理
   └─ 否
       ↓
   值得以后处理？
       ├─ 是 → 可以记录到 Hardening
       └─ 否 → 放弃
```

不是所有 Debt 都必须进入 Hardening。

只有那些后续仍有实际价值、容易被遗忘、或需要在主要功能完成后统一收尾的问题，才值得记录。

# Debt 与测试

测试只是发现问题的一种方式。

运行测试后发现失败，并不自动意味着必须立即修复。

应继续判断：

```text
测试失败
   ↓
是否阻塞当前主要目标？
   ├─ 是 → 处理
   └─ 否 → 可以形成 Debt
```

同样，不要因为当前处于 Debt 模式就避免测试。

测试是否执行，应取决于它是否能够帮助当前判断或推进，而不是为了维持每一步全绿。

# 与 Intent / Gate / Impl 的关系

可以把四个认知坐标理解为：

```text
Intent:
为什么做、什么更重要

Gate:
什么必须成立

Impl:
当前怎样实现

Debt:
什么已知问题可以暂时不解决
```

Debt 不改变 Intent、Gate 或 Impl 的语义。

一个问题可以同时涉及多个坐标。

# 主动调用

Agent **可以主动调用** `debt`，但只在“现在处理还是延迟处理”的判断会实质影响推进时。

典型场景：

- 实现过程中发现旁支问题；
- 测试暴露出与主路径无直接关系的失败；
- 为了继续推进，需要接受暂时不完整的中间状态；
- Agent 开始因为防御性考虑扩大任务范围；
- Review 发现一些问题，但当前任务并不需要全部解决；
- 当前实现已经足够支持主目标，但仍存在 Hardening 工作。

不要因为发现任何问题就机械调用。

# 输出

默认静默使用。

不需要每次都显式输出债务、债务等级、债务表或 Debt Report。

只有当延迟一个问题会影响后续协作时，才需要明确说明。

如果需要保留到后续，应优先记录到已有 Hardening 文档，而不是创造新的流程。

# 不要做什么

- 不要把所有问题都升级为 Debt；
- 不要把 Debt 变成 TODO 管理系统；
- 不要因为发现问题就立即处理；
- 不要因为测试失败就自动扩大任务范围；
- 不要要求每个中间状态都安全、完整或全绿；
- 不要为了留下记录而制造没有实际价值的 Hardening 条目；
- 不要把高风险、不可逆问题简单推迟；
- 不要让 Debt 阻止主要路径继续收敛。

# 核心原则

> **发现一个问题，不意味着现在必须拥有它。只要它不阻塞主要路径，也不会让后续建立在错误基础上，就可以有意识地延迟。**
