description: 从当前会话中搜索所有可能的 CHECKPOINT 条目，并追加到指定的 Markdown 文档。
allow_implicit_invocation: false
---

用途
- 将会话中尚未闭环的事项，以及继续处理这些事项所依赖的决策、约束和事实，记录成文档。

输入
- 当前会话的完整历史记录
- 现有的 CHECKPOINT 文档

输出
- 零个或多个可独立理解的 CHECKPOINT 条目。
- 新条目追加到 CHECKPOINT 文档中。
- 已有条目不修改、不删除

核心流程，如果任意一步不满足，则**中止运行**
1. 查找 CHECKPOINT 文档，检查数量 <= 1；否则中止运行。
2. 遍历完整会话，找出所有候选 CHECKPOINT 条目。
3. 如果候选条目数量 == 0，则正常结束，不创建或修改文档。
4. 与已有 CHECKPOINT 文档进行去重。
5. 如果新条目数量 == 0，则正常结束，不修改文档。
6. 如果文档不存在，则创建 CHECKPOINT.md。
7. 将所有新条目一次性追加到文档中。

CHECKPOINT 文档
- 名字为 CHECKPOINT.md
- 文档位置，按下列优先级查找
  1. 项目根目录下的 docs 或 doc 目录
  2. 项目根目录
- 文档创建位置，同上优先级
- 写入规则为**追加**，不能修改已有条目

搜索方法
- 逐段检查会话历史。
- 仅考虑与当前项目或任务直接相关，且在会话结束后仍需保留的信息。
- 对每个明确陈述或已形成的结果，判断它能否转化为独立候选条目。
- 搜索以下类型：
  - Issues
    - 已发现但尚未解决的问题。
    - 已复现的错误、缺陷或异常行为。
  - Decisions
    - 已明确采用的设计、方案、命名或实现方向。
    - 后续可能再次遇到，因此需要保留的已否定方案。
  - Constraints
    - 后续工作必须遵守的限制、兼容要求或边界。
  - Risks
    - 可能造成错误、回归、返工或不确定结果的因素。
  - Questions
    - 尚未回答、仍需验证或继续讨论的问题。
  - Next Actions
    - 已明确提出但尚未完成的下一步动作。
  - Facts
    - 继续处理未闭环事项所直接依赖的具体事实、现状或外部条件。
- 同一段内容可以产生多个不同类型的条目。
- 不要求所有类型都出现。

条目粒度
- 每个条目只包含一个核心信息。
- 将包含多个独立事实的句子拆成多个条目。
- 不把整个会话压缩成一个总条目。
- 不使用“本次讨论了……”之类的会话摘要表达。
- 条目脱离原会话后仍应能够理解。

与现有文档比较
- 检查候选条目是否已存在于 CHECKPOINT 文档。
- 语义相同且状态未变化的条目不重复追加。
- 状态发生变化时，追加新的状态条目，不修改旧条目。
- 新条目需要关联旧事项时，引用旧条目的类型和核心描述。

表达规则
- 使用事实性短句。
- 保留具体名称、路径、命令、参数、错误信息和版本。
- 区分已经确认的内容与推测、待验证内容。
- 不补充会话中没有出现的事实。
- 不根据常识擅自修正用户或模型在会话中的结论。
- 合并真正重复的候选条目，但不合并仅仅相关的不同事项。

追加格式
- 优先沿用现有 CHECKPOINT 文档的分类和格式。
- 文档不存在对应格式时，使用以下结构：
```markdown
## Issues

- [ISSUE] ...

## Decisions

- [DECISION] ...

## Constraints

- [CONSTRAINT] ...

## Risks

- [RISK] ...

## Questions

- [QUESTION] ...

## Next Actions

- [NEXT] ...

## Facts

- [FACT] ...
```

完成条件
- 已遍历当前会话，而不是只依据最后几轮消息。
- 会话中所有符合范围的候选条目都已被考虑。
- 候选内容已拆分为原子条目，而不是单个会话摘要。
- 与现有 CHECKPOINT 重复的内容已排除。
- 有新条目时，已写入 CHECKPOINT 文档。
- 没有新条目时，未创建或修改文档。
